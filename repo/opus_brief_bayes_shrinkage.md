## フェーズ① 縮小推定（Shrinkage）

### 目的
厩舎/騎手の「当コース勝率」表示が生の割合(wins/runs)なので、5戦1勝でも20%と出て
🔴（妙味マーク、閾値≥20%）が誤発火する。少サンプルを母集団平均に引き寄せて過信を防ぐ。

### 成果物
1. `core/bayes_stats.py`（新規・依存ライブラリなし、標準mathのみ）
   ```python
   def shrink_rate(k, n, prior_mean, prior_strength=20.0):
       """ベータ二項の縮小推定。p~ = (k + a0) / (n + a0 + b0)
       a0 = prior_mean * S, b0 = (1 - prior_mean) * S。
       n=0 は prior_mean を返す。k>n や負値は ValueError。"""
   ```
   - `prior_strength`（S）は「事前分布の重み＝仮想サンプル数」。デフォルト20。
     20戦の実績が貯まると事前と実測が同じ重みになる、という意味。docstringに平易に書く。
2. 適用箇所（表示側のみ・**関数シグネチャは変えない**）:
   - `core/jockey_jv.py` の `trainer_course_winrate()` / `jockey_course_winrate()`
     （563行・581行付近）の**戻り値dictにキーを追加**する形で対応:
     `{'runs','wins','win_rate','top3_rate'}` に `'win_rate_shrunk'` を追加。
     既存キーの値は変えない（後方互換）。
   - prior_mean はクエリ対象コース（場×馬場）の**全調教師/全騎手の平均勝率**を使う。
     毎回SQLを打つとレイテンシが増えるので、`data/course_prior_cache.json` に
     場×馬場→平均勝率をキャッシュ（初回計算・以後読み込み）。
     キャッシュ不能時のフォールバックは 0.08（おおよそ平均頭数12-13頭の逆数）。
   - 🔴マークのゲート判定（`core/consensus_view.py` 194行付近の `tcw` 利用箇所と
     `app.py` の Trainer列表示）を `win_rate` → `win_rate_shrunk` に切替。
     閾値20%は当面維持（③の後述の再検証で調整）。
3. UI表示（plain-label方針）:
   - 「ﾗﾝｸ-当ｺｰｽ勝率」の表示値はshrunk値にし、runsが少ない場合（<10戦）は
     `20%※` のように印を付け、ツールチップ/説明に「出走数が少ないため
     全体平均に寄せて控えめに表示しています」と書く。

### 再検証（必須）
- `scripts/trainer_backtest.py` が既存検証の正本。shrunk値≥20%ゲートに変えた場合の
  妙味（オッズ超え）が生値≥20%と同等以上かを確認し、結果を
  `repo/opus_report_bayes_shrinkage.md` に記録する。
  - 劣化する場合は閾値をスイープ（16/18/20/22%）して最良を報告。**自動では変えず**、
    ユーザーに提示して判断を仰ぐ。
- `tests/smoke.py` に追加: `shrink_rate(1, 5, 0.08)` が 1/5=0.20 より小さく 0.08 より
  大きいこと・`shrink_rate(20, 100, 0.08)` が 0.2 に近いこと（±0.03）・n=0でprior返し。

## フェーズ③ 「3回ルール」のベイズ化（消去理由ラーニング）

### 現状の仕組み（core/elim_reasons.py）
消去エンジンが切った馬が実際には来た時、ユーザーがその馬の条件タグ
（`compute_tags()` 43行）を台帳（`data/elim_reasons_ledger.json`）に記録する。
同じタグが `PROMOTE_THRESHOLD = 3` 回たまると `learned_tags()`（132行）が
そのタグを「自動残し」に昇格する。**3回は目視の決め打ちで、分母（そのタグが
発火した総回数）を見ていない** — 頻出タグは3回すぐ貯まるので誤昇格しやすい。

### 目的
「そのタグの馬が来た回数」だけでなく「そのタグで切った総回数」を分母に取り、
縮小推定した生還率が基準を超えたら昇格、というベイズ的な判定に置換する。

### 成果物
1. **分母の記録を追加**: 消去実行時（🧹消去フィルターが馬を切った時）に、
   切った各馬のタグを `data/elim_reasons_ledger.json` 内の別セクション
   `'fired'`（タグ→発火回数のカウンタ）としてインクリメントする。
   - 台帳スキーマが変わるので、**旧形式（entriesのみ）の読み込み互換を必ず残す**。
     `load_ledger()` は旧形式ならそのまま entries として扱い、`fired` は空dictで初期化。
   - 消去実行のフックポイントは app.py の消去フィルター適用箇所。呼び出しを
     `elim_reasons.record_fired(tags_by_horse)` の1関数追加で済ませ、app.py側の
     変更は最小限にする。
2. `learned_tags()` の判定を変更（シグネチャ・戻り値の型は不変）:
   - 分母データがあるタグ: `shrink_rate(hits, fired, prior_mean=0.156, prior_strength=10)`
     が **0.25 以上**なら昇格。
     - prior_mean=0.156 は消去クロスの検証で判明した「切った馬が来る率」の実測
       （消去精度84.4%の裏返し。66R台帳・2026-07実測）。
     - 0.25 の根拠: ベース15.6%より明確に高い＝「このタグは切ってはいけない」の証拠。
       定数は `PROMOTE_RATE = 0.25` として module 定数化し、docstringに根拠を書く。
   - 分母データがまだ無いタグ（旧台帳からの移行期）: 従来どおり出現3回で昇格
     （フォールバックとして `PROMOTE_THRESHOLD` を残す）。
3. UI（🎯消去エンジンの消去理由学習セクション）:
   - タグごとに「来た回数/切った回数」と補正後生還率を平易に表示
     （例: `距離短縮×人気薄: 3回来た/21回切った → 補正後17%（昇格まであと少し）`）。

### テスト
- `tests/smoke.py` に追加:
  - 旧形式台帳（listのみ）を `load_ledger()` が読めること。
  - `shrink_rate(3, 3, 0.156, 10)` では昇格するが（3/3は強い証拠）、
    `shrink_rate(3, 40, 0.156, 10)` では昇格しないこと（頻出タグの誤昇格防止）。

### 承認ゲート
移行互換の説明と判定例（昇格する/しないケース各2件）をユーザーに提示して完了報告。
