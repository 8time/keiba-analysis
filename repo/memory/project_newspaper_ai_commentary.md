🎭AIコメント欄（`core/newspaper_commentary.py`）の全面刷新（2026-07-23）。ユーザー評価「全然ダメ。これなら俺がLLMサイトにCSV貼った方がいい」を受けた作り直し。

**旧版がダメだった理由は品質でなく構造**（コードを読んで特定）: ①system指示が「**必ず1文・80文字以内**」②`max_tokens=120` ③**`thinking_budget=0`で思考を明示的にOFF** ④`_build_context()`が渡すのは**合議の結論だけ**（補正T/末脚/血統/騎手係数/オッズ/comboを一切見せていない）。俗説捏造を防ぐ狙いは正しかったが、縛りが効きすぎて中身が出せない状態だった。ユーザーの手動コピペが優れていたのは、`build_csv_bytes()`のフル情報（14行×108列）を渡していたから。

**新設計＝人格ごとに「見る列」を変える**。LLMに自由予想させる（俗説捏造）のでも結論をなぞらせる（無内容）のでもなく、互いに独立した検証済みシグナルを分担させる。末脚top3 ≠ 補正Ttop3 ≠ LTR上位なので**予測は捏造なしに自然に割れる**。

| 人格 | 担当(lens) | 人気帯(band) |
|---|---|---|
| 🔥ゴウ | SpurtIdx / Lap33 / 🧩重複数 | `longshot` = 6番人気以下 |
| 🛡️シズ | CorrectedT / JPower / 厩舎🔴 | `favorite` = 5番人気以内 |
| 📊カズ | LTR / Odds / OddsGap | `all` |
| 🔍ヨミ | 危険材料 / RiskFlags / Stress | `cut` = 5番人気以内から**軸回避**を挙げる |
| 🌊ナギ | 他4人の集計 | 予測せず。**集計はPython側で決定的に**（LLMに数えさせない） |

**実装上の重要な発見（2つとも実機で判明・再発防止）**
1. **LLMは馬番と馬名を対応づけられない**。候補リストを明示しても `umaban:8` と答えつつコメントは「14番ミヤラティーニ」。CSVが`Rank`順で馬番が飛ぶため行位置と混同する。→ **馬番を答えさせず馬名で受け、Python側で `_resolve_umaban()` して番号を付ける**。これで整合が保証される。
2. **帯ルールを口頭で指示しても守らない**。「5番人気以内から選べ」と書いてもシズが11番人気を選んだ。→ **`_candidates()`でPython側が候補を絞ってから渡し、返り値も`allow`集合で検証**。違反は再生成。

他に `_tidy()` でモデルの独り言（末尾の「（97文字）」）を除去、他馬名混入検査を保険として残置。

**実機検証**: 3レース連続で **5/5件生成・馬名整合OK・帯ルール遵守・予測は全員バラバラ**。所要15-22秒/レース。`gemini-3.5-flash-lite` + `thinking_level='LOW'` + `response_mime_type='application/json'`、`max_tokens=1500`（思考トークンが出力枠を食うため700では途中で切れた）。**1レース約4円**（4人格×フルCSV16kトークン）。

**⚠ 紙面での扱い**: 各人格単独の◎は**単体で儲かると検証されたものではない**。検証済みなのは『独立シグナルが一致すると複勝率が上がる』（votes=3で複勝27%）の方。よって`core/newspaper._commentary_html()`は見出しを「5人が別々のデータで予想」とし、注記に「一致が多いほど複勝圏の信頼度が上がります（**単勝の推奨ではありません**）」を入れてある。個々の◎を買い推奨に読ませない設計を崩さないこと（[[verified_tansho_roi_efficient]]/景品表示法の観点）。
