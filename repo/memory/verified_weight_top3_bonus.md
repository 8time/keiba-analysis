**発端**: 1レース(202603020611・結果11→6→9→10→1)のCSVを外部LLMに渡したところ
「33ラップ上位3頭+15 / 末脚指数上位3頭+20 / 強さ上位3頭+10 を足せば結果に近づく」という
ウェイト調整案が返ってきた。典型的な後知恵の過学習なので全レースで検定した。
（なお外部LLMの前提「11番は予測スコア16位」は**誤り**。実データでは4位。CSVの読み違い）

**検証（`scripts/weight_sweep_backtest.py`・train 29,414R / holdout 3,230R・recall@7）**:

| 設定 | train | holdout |
|---|---|---|
| base(加点なし) | 77.95% | 79.72% |
| **GPT案(33+15/末脚+20/補正T+10)** | **-0.38pp** | **-0.90pp** ❌ |
| 🌀33ラップ 上位3頭 +10 / +20 | -0.37 / -0.83pp | -0.59 / -1.08pp ❌ |
| 🔥末脚指数 上位3頭 +10 / +20 | +0.06 / -0.02pp | -0.43 / -0.46pp ❌ |
| 🔵補正T 上位3頭 +10 | +0.12pp | +0.09pp（微小） |
| **👑騎手力 上位3頭 +10** | **+0.39pp** | **+0.56pp** ✅ 唯一の両窓改善 |

recall@3・1位の勝率・上位3頭の複勝率も同じ傾向（騎手力だけが4指標すべてで改善）。

**なぜ33ラップ/末脚を足すと悪化するのか（重要な原理）**:
これらの検証済みエッジは **人気薄(6番人気以下)限定** で効く（[[verified_lap33_theory]] /
[[verified_spurt_index]]）。予測スコア全体に加点すると**人気上位馬にも同じ加点が入り**、
すでに市場が織り込んでいる(priced-in)領域を歪めてしまう。
→ **人気薄限定のエッジを全馬スコアに足してはいけない。**
現行の配線（統合ビューの穴グループ＝人気薄×comboでのみ使う）が正しい。

**教訓**: 1レースの結果に合わせたウェイト調整は必ず過学習になる。
「その馬が上がる設定」は、当たったレースを後から知っているから言えるだけ。
検証は必ず recall@7 等を全レース・train/holdoutの2窓で測る。

**副産物のバグ修正**: 影響率に新設した🔵補正タイム%の正規化方向が逆だった
（`corrected_time.field_ranks` は昇順=小さいほど速いのに `higher_is_better=True` で登録していた）。
そのままだと**最も遅い馬に加点**されていた。`_metric_keys['CTFig'] = False` に修正済み。
