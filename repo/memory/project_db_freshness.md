## 問題
JRA-VANの契約が切れると jravan.db の更新が止まるが、
**アプリのライブ表示（出馬表・過去5走）はnetkeibaスクレイプなので動き続ける**。
そのため劣化に気づけない。一方で補正T・血統/騎手統計・バックテストは
jravan.db 由来なので静かに質が落ちる。

## しきい値の根拠（実測）
2024-2026のJRA **98,760件**の出走間隔:
中央値36日 / 平均53日 / 25%点21日 / 75%点70日。

「DBがN日古い」＝その間に走った馬の**直近走が欠ける**:
| DBの古さ | 直近走が欠ける馬 | 表示 |
|---|---|---|
| 7日 | 2.1% | 🟢最新です |
| 14日 | 13.2% | 🟢まだ大丈夫 |
| **21日** | **29.4%** | 🟡そろそろ更新時期 |
| **28日** | **42.0%** | 🟠※更新時期です |
| **49日** | **60.0%** | 🔴※要更新 |
| 90日 | 85.1% | 🔴 |

## 実装
**core/db_freshness.py**: status()/should_warn()/missing_share()/how_to_update()。
実測カーブを線形補間して「欠ける馬の割合」を出す。

**app.py 左メニューの下**: 🟡以上のときだけ色付きボックスで表示。
`どうすればいい？` expanderに
- 何%の馬で前走が欠けているか
- **影響するのは補正T・統計・検証だけで、出馬表や過去5走は無関係**（不安を煽らない）
- 更新コマンド（最新日を自動で埋め込む）

## 更新方法（JRA-VAN契約時・数分で終わる）
```
C:\Users\kimnhaty\pythonx86-312\tools\python.exe scripts\jvlink_ingest.py \
    --from <DBの最新日>000000 --option 1
```
`--option 1`=差分のみ。`--option 4`は全履歴で数時間かかるので普段は使わない。
**32bit Python必須**（JV-LinkのCOMが32bitのため）。[[project_jravan_setup]]
