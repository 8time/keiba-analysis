✨ Race Scanner(バッチ)を刷新(2026-06-15)。旧=スコア差gapの「難易度分類器」→新=1日のカードから「買えるレース×妙味馬」を抽出。

**単複乖離(検証済・目玉)**: 「単勝が長い(≥10倍)のに複勝(mid)が短い(≤3.0倍)」馬は単勝が過小評価。
- 検証(オッズDBは1993-96と直近2026のみ収録→90年代n=13.5万で方向性確認): 単≥10×複≤3 → 勝率2.5%→7%・勝利残差+0.017・単勝回収85.9%(無印68.5%・+17pp)。
- ❌資料の「単勝÷複勝の比率≥7」単純ルールは逆効果(ただの人薄プロキシ・残差マイナス)。**比率でなく『単勝の絶対水準が長い×複勝が短い』の複合条件**が正しい(資料を鵜呑みにせず修正)。
- ⚠単勝回収85.9%は単体100%未満→「妙味フラグ＋連系(ワイド/3連複)の素材」用途。ライブ複勝オッズで点灯。

**実装**:
- core/value_scanner.py 新設(純粋関数): race_skip_reasons(見送り=新馬/未勝利/2歳/障害/少頭数≤10/単勝1倍台)、race_value_score(妙味度0-100=頭数/1番人気オッズ/上位3頭拮抗/中穴黄金ゾーン/ハンデ/フルゲート/不良/ローカル芝/オープン/芝短ダ長)、tanpuku_divergence、horse_value_factors(±ファクターは[[project-elimination-engine]]と同一定義を流用)。

## 絞り込みの実態（2026-07-23調査・バグ修正）

**「該当するレースはありませんでした」の主因は設定ミスではなく母数**。実測(34,882レース):
- 妙味度≤45(堅い) = 36.4% / **本線向き = 6.7%** / 両方 = **6.15%**
- 1日36Rなら平均**2.2レース**しか出ない。12Rだけスキャンだと平均0.7R＝0件が普通に起きる
- しかも**本線向きの92.3%は既に妙味度45以下**（中央値30）なので、妙味度フィルタを緩めても 2.2R→2.4R にしか増えない＝**絞り込みの正体は本線向き判定そのもの**
- 推奨設定: 荒れ度は「こだわらない」、決着タイプのみ「本線向き」、対象を1日全場(36R)に、「見送りを隠す」はOFF(本線向きは少頭数で出やすく、少頭数は見送り条件にも入るので二重に削られる)

**バグ: `min_value_horses` が代入のみのデッドコード**だった（何を選んでも結果が変わらない）。修正の過程で1つ学びがある:

⚠ **`scanner_priority()` にしきい値フラグを足す案は無効**。実装して実測したら全しきい値で並びが完全に同一だった。理由は `n_v`(妙味馬数)が直後のキーにあり、**しきい値判定は n_v の単調関数**なので順序が一致してしまうため。この設定を意味あるものにするには**絞り込みにするしかない**。→ app.py側でフィルタとして実装し、ラベルも「優先」→「に絞る」に修正（実態と一致させた）。`scanner_priority` は元の6要素タプルのまま＝バックテスト/スモークは挙動不変。
