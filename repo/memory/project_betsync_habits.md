資金管理マニュアル資料を[[project_betsync_money]]と突き合わせた結果、
**大半は既に実装済みか、こちらの方が正確**だった（連敗数は理論値でなく実測、
追い上げ否定は主張でなく退場率98.2%の実測）。
足りなかった3点だけを追加した。

## 追加した3つ
| # | 内容 | 実装 |
|---|---|---|
| ① | **気分の記録** | `bets.mood`（冷静/やや熱/熱い）＋ `mood_report()` |
| ② | **見送りの記録** | `skips` テーブル ＋ `record_skip/settle_skip/skip_report()` |
| ③ | **ルール逸脱の履歴** | `bets.deviation` ＋ `deviation_report()` |

**BetSyncに「🧘 自分の癖を見つける」expander**（3タブ）。
買い目入力フォームに気分・逸脱のプルダウンを追加。

## なぜ必要だったか
- ①は資料の「記録すべき6項目」で**唯一欠けていた**もの。
  既にある損失分類・改善ルールと組み合わせると
  「熱くなった時だけ負けている」が数字で出る。
- ②は**資料にも無い発想**。台帳が「買ったもの」しか持たないと、
  一番効く判断（[[verified_hot_hand_selective]]の「買わないこと」）を評価できない。
  買っていた場合のROIが100%未満なら見送りは正しかったと分かる。
- ③は資料の核心「修正すべきはルールからの逸脱のみ」を測定可能にするもの。
  逸脱なしを対照群にしてROI差を出す。

## 注意
- 3つとも**自己申告の実観測台帳**。検証済みシグナルではない
  （[[project_elim_reasons_learning]]と同じ扱い）。
- 画面には「当てるための機能ではない／自分の癖を見つけるための機能」と明記。
- 見送りの答え合わせで「当たってた」を押した時の払戻は
  実測中央値（3連複C中庸2,535円）で概算。正確さより傾向を見る目的。

## 実装上の落とし穴
`_lg = money.Ledger()` の定義が**このブロックより後**（app.py 1716行）だったので、
expander内で自前にインスタンスを作っている。同じSQLiteを開くだけなので二重生成可。

## ⚠資料との前提の違い（重要）
資料は「**回収率120%の神予想を持っていても**」という前提で書かれている。
しかし本プロジェクトの検証では回収率100%超の買い方は見つかっていない（最良=D鉄板90%）。
したがって資金管理の目的が変わる:
| | 資料 | このアプリ |
|---|---|---|
| 目的 | +EVを複利で最大化 | **-EVでどれだけ長く生き残るか** |
| ケリー | 最適配分 | エッジが負なら「賭けるな」と言う道具 |
資料を読んで「120%前提」の設定にすると危険なので、既定値は変えていない。
