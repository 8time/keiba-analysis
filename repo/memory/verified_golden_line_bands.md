黄金ライン(騎手×調教師の連対率)の帯別検証。scripts/golden_line_backtest.py、jravan.db 2016-2026・77.5万騎乗、race_key未満の累積のみで算出(リークフリー)。

**3着内残差(人気統制) train / holdout**:
- 25-35%: +1.25pp(z+10.1) / **+0.13pp(z+0.4)** ← holdoutで消える=判定に使わない
- **35-40%: +2.44pp(z+10.8) / +2.48pp(z+3.3)** ★両窓最強=期待値ゾーン
- 40-50%: +1.28pp(z+4.4) / +0.99pp(z+1.2)
- 50%+: +0.39pp(z+0.7) / -0.10pp(z-0.1) ← 強いが人気で織込み済み

**人気薄(6番人気以下)単勝ROI**: 35-40%=95.9%/88.5% が最良、40-49%=68.4%/48.0%、25-34%=72.9%/81.5%。**どの帯も100%未満**＝儲かる印ではなく軸信頼度・手を伸ばす順番の目安。ゲートを40%→35%にすると該当2.7%→6.4%だが残差は+1.10→+1.87pp(holdout z+1.0→+3.1)と**濃くなる**(希釈ではない)。

**実装(2026-07)**: core/jockey_jv.py に GOLD_TOP2_WEAK=0.30 / GOLD_TOP2_GATE=0.35 / GOLD_TOP2_STRONG=0.40 と `golden_line_mark()`(表示・🥇🥇/🥇/△)・`is_golden_line()`(判定・△を除く35%以上)を新設。消去エンジン/合議/妙味スキャナ/J5表示の4か所に散っていた閾値ベタ書きを全てヘルパー経由へ統一(smokeで復活検知)。△(30-35%)は目視用の参考表示のみで判定ゲートには通さない。

**係数段は検証の上で据え置き確定(2026-07)**: `jockey_factor`の段(0.30→×1.035 / 0.40→×1.07)は残差の向きと逆に見えるが、**変えても順位は良くならない**と実測。scripts/jockey_coef_recall7_backtest.py:
- 能力ベース win@7: train 現行+0.20pp / 検証準拠+0.15pp、holdout 現行±0 / 検証準拠**-0.05pp**
- 市場ベース(オッズ逆数) win@7: 両窓とも全変種±0.01pp以内＝差が出ない
- 理由: 係数差3.4%(1.035↔1.07)×該当3-6%では上位7頭の境界をまたぐ並べ替えがほぼ起きない。**残差(オッズ超過)と順位(recall@7)は別問題**。

また当初「係数を触るとProjected Score/LTRが動く」と書いたのは**誤り**。実査の結果 `jockey_factor` の呼び出しは app.py の J5表1か所のみで、Projected Score/LTR/買い目/消去/合議には一切入らない(動くのはJ5表の並びだけ)。

**バックテスト設計の教訓**: 係数(乗算)を検証するときベーススコアは必ず「正の値・大きいほど良い」にする。負値(-ninki等)だと×1.07が順位を下げる逆効果になり全変種同一という誤結果が出る。また『頭数-人気+1』の線形尺度は7/8位の隣接比が1.09-1.11で最大係数1.07を超えるため構造的に一切逆転せず代理として不適(実測0/31,419レース)。実Projected Scoreの隣接比は約1.056なので、`1-ability_score`(隣接比1.063)かオッズ逆数を使う。

**Why**: 202609011010(レグルスS)で🥇該当3頭が1-2-3着した観察がきっかけ。ただし1着4番は実測33.6%で、旧🥇表示が30-40%を意味していたための見え方。n=1の一致から閾値を動かさず、77.5万騎乗で帯別に測ってから決めた。

**How to apply**: 黄金ライン関連の提案は必ずこのスクリプトの枠(帯別×人気統制残差×train/holdout×人気薄ROI)で検証。表示ゲートと判定ゲートを分ける設計を崩さない。
