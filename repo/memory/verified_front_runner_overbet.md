ユーザー仮説「フィールド平均PCIに近い × 本物の先行 × 軸候補 = 入着しやすい」を検証
（`scripts/pci_front_axis_backtest.py`・1-5番人気・オッズ20分位で統制した複勝率残差）。

**結果は仮説の逆。ただし副産物が大きい:**
- **本物の先行（平均通過位置比率 < 0.28）は軸として過剰人気**
  train -1.61pp(z-6.84) / holdout -1.86pp(z-3.23) ★両窓
- 前走1着との重複を除いた**純粋な先行効果**でも train z-4.00 / holdout z-2.44 ★＝**独立に効く**
- **先行 × 前走1着 = 最悪**（-4.63pp / -3.41pp）
- **非先行 × 前走1着でない = 最良の軸**（+0.82pp / +1.00pp ★両窓）
- → `axis_selector.FRONT_DEMERIT = 1.2pp`（[[verified_axis_ng_claims]]のPREV_WIN_DEMERITと**加算**）

**[[verified_legtype_axis]]と矛盾しない**: 先行馬の"生の"複勝率は確かに高い(44.1%)。
だがオッズがそれ以上に高い＝過剰人気。前走1着とまったく同じ『絶対値は高いが割高』のパターン。
あちらは生の率、こちらはオッズ統制後の残差を見ている。

**PCI部分は今回も無**: 「フィールド平均PCIに近い」単体は残差 z+0.69/+0.64 でゼロ。
交差にしても上乗せ無し（[[verified_pci_pricedin]]＝PCI完全終了 を再確認）。

**Why:** 「よく3着内に来ている」と「軸として買う価値がある」は別物。人が直感で拾う特徴
（先行・連勝中）はすでに市場が過剰に織り込んでいる。**生の複勝率でなく残差で見る**こと。

**How to apply:** 軸の信頼度は「派手さの無い人気馬」を上に置く。先行/前走1着は切らないが割り引く。

**バグ教訓:** `results.time` は **MSSt形式**（1377 = 1分37秒7）。1/10秒の通し値ではない。
最初これを time/10 と誤読してPCIが壊れ（中央値126）、標本が7,749行まで落ちた。
正しくは `(time//1000)*60 + (time%1000)/10`。`ato3f` の方は素直に 1/10秒（381 = 38.1秒）。
