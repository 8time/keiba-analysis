**症状**: SRA「🏇騎手係数込み総合スコア」で**騎手係数が全馬1.000・黄金ライン列が常に空欄・
内訳が全馬「データ少」**。ユーザーが「黄金ラインに何か書いてあるのを見たことがない」と指摘して発覚。

**原因**: `core/jockey_jv.py` の下位集計4関数
（`jockey_base_stats` / `jockey_trainer_combo` / `jockey_usm` / `jockey_power`）が
`_norm()` しか通しておらず、**`resolve_jockey_name()` を通していなかった**。
netkeiba出馬表は略記（`横山武` `岩田望` `☆団野` `Ｃ.ルメール`）だが jravan.db は完全名
（`横山武史` `岩田望来` `団野大成` `ルメール`）。→ DB直引きで**ヒット0件** → `rides < 30` の
分岐に落ちて `{'mult': 1.0, 'note': 'データ少', 'gold': None}` を返していた。
`武豊` など略記＝完全名の騎手だけ偶然動いていたのが発見を遅らせた。

**修正**: メモ化した `_resolved()` を下位4関数に内蔵。完全名を渡した場合は同じ名前が返る（**冪等**）
ので、DB名で回すバックテスト・検証値は一切変わらない。
`jockey_power` は呼び元（consensus_view）が明示的に resolve していたため無事だった
（だから強適テーブルの👑騎手力だけは正しく出ていた）＝**同じ関数群でも呼び元次第で症状が出たり出なかったりした**。

**修正後の実測**（202608020211）: 横山武 1.0→**0.945**（USM94/場連対16%）、
岩田望 1.0→**1.005**（黄金21%/209走）、川又 1.0→**0.922**、武豊 1.018。
黄金ラインは連対30%+で🥇 / 40%+で🥇🥇。全騎手×調教師の**7.3%しか該当しない**ので、
空欄が多いこと自体は正常（ルメール×特定厩舎で🥇🥇を実測確認）。

**回帰テスト**: `tests/smoke.py` の `jockey_jv.略記の騎手名解決(係数1.0固定バグ回帰)`。

**Why / 教訓**: **UIで「全部同じ値」（全馬1.0・全部空欄・全部『データ少』）が並んでいたら、
計算式ではなく名寄せ（ID解決）の失敗をまず疑う。** 見た目が「機能していない」ではなく
「無難なデフォルト値」で埋まるため、バグに見えず何ヶ月も放置されやすい。
同型の前例: 人気列をX座標固定で取得してNoneになる（CLAUDE.md 過去の失敗事例）。
