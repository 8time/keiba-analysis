ユーザー提示の動画（地方競馬・佐賀）の手法「①同距離の過去5走ベストタイム上位3頭 ②その3頭が1〜3番人気以内か確認 ③揃えばサービスレース」の検証（2026-07-23・`scripts/time_pop_overlap_backtest.py`・31,613レース・補正T被覆率91%）。

**手法の正体＝補正T(CorrectedT)の簡易版**。ノートの数字(33.2/32.2…)は走破タイム「1分32秒2」の分を省いた略記。うちの補正Tとの差は**馬場差・クラス差の補正が無い**こと（同日同コース偏差を引いていないので良馬場と重馬場を同列比較してしまう）＝**上位互換が既に実装済み**。ユーザーの読み「妙味度が低い堅めのレースで使う手法」は[[verified_corrected_time]]（1-2番人気×図トップ3で複勝+4.8〜5pp／人気薄は+1.6pp＝軸寄りの道具）と完全に一致。

**新しかったのは「馬選び」でなく「レース選別」に使う点**。ユーザー発案の逆転版「重複が少ない＝予測困難＝見送る」を検証した。

| 重複 | 割合 | 荒れ率(holdout/recent) | 本線決着 | 1番人気複勝 |
|---|---|---|---|---|
| 0 | 13% | 61.4% / 56.1% | 25.5% / 27.1% | 55.2% / 65.4% |
| 1 | 43% | 53.6% / 48.8% | 28.6% / 27.4% | 61.9% / 63.9% |
| 2 | 38% | 45.2% / 47.0% | 35.5% / 37.0% | 68.4% / 66.6% |
| 3 | 6% | 41.3% / 43.1% | 43.9% / 55.2% | 74.1% / 81.0% |

**① 荒れ予測としては不採用（priced-in）**。凍結オッズロジット(AUC0.690)との残差は holdout +1.74/+1.84/-0.46/-0.32pp、recent -1.21/-2.90/+0.04/-0.16pp と**単調でも有意でもない(|z|<2)**。[[verified_arare_field_pricedin]]の「実力スプレッド系はAUCゲイン≈0」がトップ3重複という鋭い形でも再確認された。荒れ予報の特徴に足してはいけない。

**② 軸信頼度の目安としては本物**。生の値は強く単調で、1番人気の複勝率が55%→62%→68%→74%(holdout)。オッズを超えないだけで外れてもいない＝**表示用の道具としては使える**。

**③ 見送り運用は閾値注意**。「重複≦1を見送る」は見送り率55-58%で**切りすぎ**（半分以上を捨てて荒れ率55%→45%になるだけ）。使うなら逆に**重複3(全体の6%)を「軸が特に信頼できるレース」として拾う**方向。

**How to apply**: 動画の手法を再実装する必要はない（補正Tが上位互換）。レース選別に使うなら「軸信頼度の表示」に限定し、荒れ予報の計算には入れない。[[verified_solid_race_inverse]]（堅いレース条件の逆転もpriced-in）と同型の結論。

## 実装済み（2026-07-23）

`core/axis_selector.race_axis_confidence(horses)` を新設。`horses=[{'umaban','ninki','ct_fig'}]` を受け、補正Tトップ3と人気トップ3の重複数(0-3)＋日本語ラベル＋1番人気複勝率の目安を返す。補正T保有が3頭未満／人気が3頭分揃わないレースは `None`（実測で6レース中1レースは判定不能）。

**⚠ 既存の `axis_confidence()` とは別物**。あちらは「1頭ごとに軸マークを付けるか」の判定器（pop/odds/prev_win_margin等を受ける）。こちらは**レース単位**。名前が似ているので混同しないこと。

**表示先**: SRAの荒れ予報の直後（app.py）。一致3頭なら `st.success`（🎯勝負向き・全体の6%）、0頭なら「軸を厚く買わない方が無難」、それ以外は `st.caption`。数字だけでは良し悪しが分からない指摘（同日に7回目）を踏まえ、**「1番人気が3着以内に入る率 約N%」を必ず併記**している。

**データ源**: `df['CTFig']`（生の補正T・負=速い。app.py上流で `_sig_raw` から列として付与済み）と `Popularity`。新規のDB引きは発生しない。

**荒れ予報には足していない**（残差|z|<2で非有意のため）。表示専用の位置づけを崩さないこと。

## 🔍Race Scanner への横展開（2026-07-23）

本来の使い方（1日36Rから勝負レースを拾う）ができるようScannerにも配線。

**追加コストはほぼゼロ**。`core/value_scanner.horse_value_factors()` が既に `jj.resolve_horse()` で血統番号を引いているので、そこに `corrected_time.get_figure()` の1クエリを足して戻り値に `ct_fig` を載せるだけで済んだ（新規の馬名解決は発生しない）。実測で14/14頭の補正Tが取れた。

- `core/value_scanner.horse_value_factors()` … 戻り値に `ct_fig`(生の補正T・負=速い) を追加
- `app.py` Scanner … `_rc_pool` に集めて `race_axis_confidence()` → 結果を `results[].axis_conf` へ
- Scanner一覧に **🎯軸N/3・ラベル** バッジ（一致3=緑／0=橙／他=灰、ホバーで「1番人気が3着以内に入る率 約N%」と検証根拠）
- `core/newspaper._SCAN_KEEP` に `axis_conf` を追加 → スキャン結果のディスク保存にも載る（別タブの新聞発行から参照可）

⚠ **判定には「妙味馬ファクター照合(do_factor)」がONである必要がある**。OFFの軽量モードでは `horse_value_factors` を通らず `ct_fig` が得られないため `axis_conf=None`（バッジ非表示）になる。
