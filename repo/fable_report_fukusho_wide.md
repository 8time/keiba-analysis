# Fable案件③ 報告書: 複勝/ワイドEV最適化 — 「初の+EV」はリークの幻だった（反証）

- 依頼書: `repo/fable_brief_fukusho_wide.md`
- 実装: `scripts/fukusho_wide_ev.py`（combo長期化＋複勝/ワイドEV・全セクション再現可能）
- 成果物: `data/fukusho_wide_ev.json`（全数値）/ CSV基盤拡張（`data/export/horse_races.csv` を
  **2016年以降・48.6万行**へ拡張＋`sire`/`bms`/`sire_winroi`列追加）
- 検証窓: 2016-2023（仮説発見前＝真のout-of-sample）/ 2024-2026（発見期）/ 年別、
  bootstrapは**レース単位クラスタ**90%CI、配当は実データ（複勝網羅率99.4%・事前複勝オッズ100%）
- 実行日: 2026-07-07

## 結論（3行・正直）

1. **出発点の「combo≥4複勝ROI123.5%=+EV」はlook-aheadリークの幻**と判定。元comboの構成モジュールは
   凍結DB全期間の静的統計を使っており、歴史レースから見た**未来**を含んでいた（補正T `get_figure`＝
   その馬の未来走を含むベスト図が最強のリーク経路。騎手power・血統辞書も同様）。
2. 全シグナルを厳密leak-free化した**combo6p**では、複勝は全期間・全帯で−EV
   （combo6p≥4: 2016-23=81.3% / 2024-26=84.5%、単調性はあるが控除の壁の内側）。
   **ワイド・オッズ帯・単複乖離・他エッジ単体もすべて−EV**。複勝/ワイドプールも
   このシグナル集合では効率的だった。
3. **利益化ラインは主張できない**。3連単の轍（分散の幻）は回避したが、今回は
   「リークの幻」だった。comboは**的中率の並べ替え道具（相手絞り）としては生き残る**が、
   +EVの買いルールとしては死んだ。

## リーク判定の証拠（scripts/fukusho_wide_ev.py ⑥・決定的）

本物のエッジなら「leak-free版でも上位に見える群」が良いはず。実際は逆:

| 元combo≥4（2024+・複勝） | n | ROI | 90%CI |
|---|---|---|---|
| ∧ combo6p≥3（過去情報でも一致） | 704 | 104.6% | [88.2, 122.9] 非有意 |
| **∧ combo6p≤2（未来情報でのみ上位）** | 617 | **144.2%** | **[121.0, 167.9]** |
| 2024年（未来情報 多） | 518 | 110.0% | [88.7, 132.5] |
| 2025年 | 549 | 148.7% | [125.2, 172.3] |
| **2026年（未来情報 最少）** | 254 | **97.7%** | [72.3, 126.6] **消滅** |

利益がちょうど「過去情報では見えない場所」に住んでおり、未来情報が減る2026年で消える
＝look-aheadリークの教科書的署名。combo≥3でも同型（一致群92.1% vs 不一致群109.9%）。

### リーク経路（コード実査）
- `core/corrected_time.get_figure(ketto, surface)` → 事前構築の `horse_fig` テーブル（全期間）
  ＝**馬単位の直接リーク**（2024年のレースにその馬の2025-26のベスト時計が混入）。
- `core/jockey_jv.jockey_power(name)` … before_key**未指定**で呼ばれていた（キャッシュ生成時）
  ＝騎手の未来成績を含むコホートリーク。
- `core/bloodline.blood_score / lookup_sire_stats` … 全期間静的辞書＝種牡馬コホートリーク。
- ※**ライブ運用のcombo自体は不正ではない**（当日時点では全統計が過去）。誤っていたのは
  「歴史レースを今日の統計で評価したバックテスト数値」。combo0=4%→4=19%等の既公表テーブルも
  楽観側に膨らんでいる（leak-free版の実力は下記）。

## leak-free長期版 combo6p の実力（2016+・人気薄7番人気以下・実配当）

combo6p = 同じ6シグナルの厳密過去限定版（🔵h7_rank≤3 / 🔥末脚top3 / 🧬血統rolling top3 /
🧬産駒回収rolling≥100% / ⚡33適合 / 👑騎手form top3）。元comboとの相関0.479。

| combo6p | 2016-23 複勝率 / ROI | 2024-26 複勝率 / ROI |
|---|---|---|
| 0 | 5.0% / 58.2% | 4.6% / 52.0% |
| 2 | 8.9% / 72.0% | 8.7% / 68.0% |
| 3 | 11.0% / 77.9% | 11.4% / 76.9% |
| ≥4 | 13.9% / 81.3% [75.3, 87.5] | 14.1% / 84.5% [74.4, 95.1] |

- **的中率の単調性はleak-freeでも本物**（5%→14%）。= 相手絞り/ショートリスト用途は正当。
- ROIは年別11年間で一度もCI下限>100%なし（最良2019=102.9%中央、CI跨ぎ）。
- オッズ帯最適化: 最良でも単勝10-20倍帯86.2%・複勝5-8倍帯84.2%＝どの帯も−EV。
- ワイド: combo×人気1-4が最良で81-82%（floor超・−EV）。combo×combo=44%は最悪（同レースで
  人気薄2頭とも3着内の要求が過大）。
- 他エッジ単体（補正T/末脚/血統/回収/33/騎手）: 70-75%で全て−EV。
- 単複乖離（単≥10×事前複≤3）: 72-75%＝**勝率リフト（検証済）はあるがEVは負**（人気に織込み）。

## 実装への影響（要対応）

1. `scripts/fukusho_combo_backtest.py` に反証注記を追記済み（再利用防止）。
2. **複勝買い目の配線（ブリーフのタスク6）は中止**が正しい判断。妙味馬リスト（案件①）は
   「網羅ショートリスト」の位置づけを維持し、+EV主張はしない（既に注記済みの方針と整合）。
3. 過去のcombo関連の公表数値（3着内率テーブル・穴馬ハンターのcaption等）は楽観側。
   正確な期待値はcombo6p表（上記）を使うこと。キャッシュ `vh2_combo_cache.json` を
   バックテストのROI根拠に使うのは禁止（リーク持ち）。
4. 将来「歴史バックテスト」でモジュールスコアを使う際は before_key 対応（jockey_powerは対応済・
   get_figureは非対応＝CSVのh7系で代替）を必ず確認。**CSV特徴ストア（全列shift(1)厳守）を
   バックテストの正本にする**のが再発防止策。

## 方法論メモ（今後の+EV探索の教訓）

- 「+EVを見つけたら疑うべき順」= ①リーク（今回） ②分散の幻（3連単の轍・bootstrap CIで対処）
  ③多重検定。今回の**リーク署名テスト**（一致/不一致分解・未来情報量の年勾配）は汎用なので、
  今後の+EV候補には必ず適用する。
- 複勝/ワイドの「プールが薄い=歪みが残る」仮説自体は棄却されていないが、**このシグナル集合では
  歪みを見つけられなかった**が正確な結論。
