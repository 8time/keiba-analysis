## 0. いま何を確かめるか

俗説ハンターは「世間の話を全部数える」実験場で、予想には足していない。
次にやりたいのは、**今回のレースで信用してよい俗説だけを自動で選ぶ**こと。

測るのは「俗説が正しいか」ではない。

**今回と似た過去で、その俗説が結果をどれだけ改善したか。**

仮説は2つ。

1. 俗説の効きは普遍ではなく、レース環境で切り替わる。
2. その環境は、コース・距離・馬場・開催の直前バイアスから、**そのレースより前の情報だけ**で判定できる。

全体では否決済みの俗説を、条件付きで復活させてよいかを見る。
面白そうだから実装する、は禁止。

## 1. やってはいけないこと

- 同じレースの着順・通過・結果脚質で、そのレースの有効度を判定する。
- 当日トラックバイアスに、**まだ走っていないレース**（同日の後のレース）を使う。
- 「数字が良かった俗説」をそのまま採用する。
- 少サンプル（馬200頭未満、または類似レース80R未満）を強いシグナルにする。
- 多数の条件を試して、一番成績が良かった組み合わせだけ残す。
- 有効度を最初から 0〜100 の掛け算式にする。
- 「競馬では一般的に○○」で補強する。
- 俗説有効度を馬の Rank / 穴馬ハンター / 3連単に足す（この工程では禁止）。
- `recommend_trio` / `fixed_pool` のシグネチャを変える。
- 新ライブラリを足す。

holdout で再現しなければ、機能ごと却下する。

## 2. データと検証窓

このプロジェクトの標準を使う。新しい分割を発明しない。

| 窓 | 定義 | 使い方 |
|---|---|---|
| train | `day <= 20241231` | 類似度の定義・採用閾値の候補を見る |
| holdout | 2025年 | 採否の本番 |
| recent | `day >= 20260321`（DB上限 2026-06-21） | 直近でも崩れないか |

ローダー: `scripts/csv_data.py`（`data/export/horse_races.csv` / `races.csv`）。
無ければ先に `python scripts/export_features_csv.py`。

馬行の事前確定列（この検証で使うもの）:

- キー: `race_key`, `day`, `jyo`, `surface_code`, `kyori_int`, `race_num`, `field_size`
- 俗説判定: `waku_n`, `zogen`, `days_since`, `avg_pos3`, `pos_ratio3`, `ninki`, `win_odds`
- 結果（ラベルのみ）: `chakujun`, `top3`, `win`
- レース側: `races.csv` の `baba_code`, `race_num`, `cushion`, `dirt_moisture`

`kyakushitsu`（結果脚質）と当該レースの通過順は**特徴に使わない**。脚質は CSV の過去平均 `avg_pos3` / `pos_ratio3` だけ。

残差の出し方は既存どおり。人気別ベース複勝率からの差と z。
参考: `scripts/csv_data.resid_z`、`scripts/gender_folklore_backtest.py`。
主指標は**複勝残差（pp）**。単勝率・複勝率・単勝ROI・複勝ROIも併記するが、率が高いだけでは採用しない。

最低標本: 残差判定は **n≥200頭**。類似レース集合は **≥80R**。足りないセルは「判定不能」であり、有効ではない。

## 3. 最初に見る俗説（10個。主観で増やさない）

画面のカタログ（`core/folklore_lib.py`）と対応させる。判定はライブ俗説と同じ向きにする。

| id | 俗説 | 該当馬（事前確定） | 既存の全体結論（出発点） |
|---|---|---|---|
| `draw_inner` | 内枠有利 | `waku_n` 1〜3 | ダート穴帯は織込み。人気馬の外枠は別エッジ [[verified_dirt_draw_bias]] |
| `draw_outer` | 外枠有利 | `waku_n` 6〜8 | 同上。不良の外枠は不利側 [[verified_heavy_track_bias]] |
| `style_nige` | 逃げ有利 | 過去平均 `avg_pos3 <= 2` | 生の率は高いが軸としては過剰人気が多い [[verified_front_runner_overbet]] |
| `style_senko` | 先行有利 | 過去 `pos_ratio3 <= 0.28`（俗説 `front_habit` と同じ） | 同上 |
| `style_sashi` | 差し有利 | 過去 `pos_ratio3 >= 0.50` | 差しROI俗説は否決寄り [[verified_legtype_axis]] |
| `rot_layoff` | 休み明け好走 | `days_since >= 90`（俗説 `layoff_buy`） | 人気馬×中9週は残差マイナス・ROIフラット [[verified_rotation_weight_demerit]] |
| `rot_second` | 叩き2走目 | 前走が `days_since>=90` の直後（今回の間隔は短い） | 全体では未分離。CSVに無ければ `ketto_num` 履歴から leak-free で作る |
| `wt_up` | 馬体重増 | `zogen >= +10` | 全体は fade 側 [[verified_paddock_weight]] |
| `wt_down` | 馬体重減 | `zogen <= -10` | 同上 |
| `wt_big` | 大幅増減 | `abs(zogen) >= 16`（消去の `zogen16` と同じ） | 消去の fade 材料。買い復活するかだけ見る |

「これは効きそう」で 11個目を足さない。
10個で A/B/C が付いたあと、必要なら次工程で距離短縮・前走凡走などを足す。

叩き2走目の定義をスクリプト先頭に1つ書いて固定する。後から一番成績の良い定義に差し替えない。

## 4. 「今回に似た過去」の作り方

完全一致だけにしない。ただし類似度の式をたくさん試して勝者だけ残すのも禁止。

**事前に3案だけ**書き、train で1つ選んで freeze し、holdout で評価する。

距離帯: 〜1400 / 1401〜1800 / 1801〜2200 / 2201〜。
馬場グループ: 良 / 稍重 / 重不良（稍重は全体では織込み済みだが、セルは分ける）。

### 案S1（きつい）

同じ `jyo` + 芝ダ + 距離帯 + 馬場グループ。重み 1。それ以外 0。

### 案S2（一段ゆるい）※推奨の出発点

| 条件 | 重み |
|---|---|
| S1と同じ | 1.0 |
| 場・芝ダ・距離帯は同じ、馬場グループだけ違う | 0.5 |
| 芝ダ・距離帯は同じ、場が違う | 0.25 |
| それ以外 | 0 |

### 案S3（距離だけ連続）

同じ芝ダが必須。  
`exp(-|距離差|/200) × (同じ場なら 1.0、違えば 0.3) × (馬場グループ同じなら 1.0、違えば 0.5)`。

選ぶ基準（train のみ）: 後述の「予測した効果量」と「そのレースで実際に出た効果量」の Spearman。一番単調な案を1つ freeze。holdout で作り直さない。

類似集合を取るとき、対象レース自身と **その日より後のレースは入れない**（時系列）。

## 5. 各俗説の「効果量」

類似レース集合の中で、該当馬 vs 非該当馬（または場全体）を比べる。

必ず出す数字:

- n（頭） / レース数
- 勝率・複勝率
- 単勝ROI・複勝ROI（複勝配当が CSV に無いなら単勝ROIと複勝残差で代替し、複勝ROIは「無し」と明記）
- **全体平均との差**（複勝率差 pt）
- **人気統制残差**（主指標）と z

例: 類似条件の先行馬 複勝 31.2%、同条件全体 24.5% → +6.7pt。
これと残差が食い違うときは、残差を採否に使う（市場が既に織り込んでいるため）。

効果量の符号: 「有利」俗説なので、該当馬の残差がプラスなら俗説どおり。マイナスなら俗説の逆。

---

## 6. トラックバイアスは必ず分ける

中心仮説なので、全期間平均だけで「内枠有利」と書かない。

### 長期

類似集合（§4）での枠・脚質の残差。これが「昔からこの条件は内」の部分。

### 直前（リーク無し）

そのレースより前に終わった、**同じ開催日・同じ場・同じ芝ダ**のレースだけ。

| 直前窓 | 使うレース |
|---|---|
| 同日 | `day` 同じ、`jyo` 同じ、芝ダ同じ、`race_num` が今回より小さい |
| 開催 | 同じ場の直近開催（同日が2R未満のとき）。今回の `race_key` より前 |

同日が 2R 未満なら直前バイアスは **欠損**。ゼロ埋めしない。欠損のレースは「Dモデルは使えない」とし、C と比較する母数を明記する。

直前で見るもの（当該レースの通過は使わない）:

- 勝馬の枠が内（1-3）か外（6-8）か
- 勝馬の過去脚質（`avg_pos3` / `pos_ratio3`）が前寄りか後ろ寄りか

「過去は内、今日も内」と「過去は内、今日は外差し」を分けて集計する。

既存の当日逆算は `core/track_bias.py`（前半の傾向は後半も続く、は検証済み）。ロジックをコピーするなら **そのレースより前** だけにすること。

## 7. 「今回有効度」の部品（まだ掛け算しない）

俗説ごと・レースごとに、生の列を出す。0〜100 にしない。

| 列 | 意味 |
|---|---|
| effect | 類似集合での複勝残差（pp） |
| raw_diff | 類似集合での複勝率差（pt） |
| n_horse / n_race | 標本 |
| bias_agree | 直前バイアスの符号が effect と一致なら +1、逆なら -1、欠損 0 |
| year_sign | train 内で残差プラスだった年の割合 |
| similar_w | 使った類似度案の識別子 |

この表を train で見て、

- effect が大きいほど、そのレースの実現残差も大きいか
- bias_agree=+1 のとき、C より D が良いか

を先に見る。関係が単調なら、そのあとで 0〜100 の付け方を提案する。単調でなければスコア化しない。

## 8. 比較モデル（必須）

レース単位で「この俗説は今日有効か」を事前に言い、実現した該当馬残差で採点する。

| モデル | 事前に使う情報 |
|---|---|
| A | 俗説を使わない（ベース。該当馬の残差は「何も知らない」） |
| B | 全レース共通の固定効果（train 全体のその俗説の残差） |
| C | 類似条件だけの効果（§4） |
| D | C ＋ 直前バイアス一致（§6） |

見たいのは **D が C を holdout で安定して上回るか**。
上回るなら「有効性はトラックバイアス依存」を支持する。
C も B も同じなら、条件分解する意味がない → 画面の「今回有効」は作らない。

馬評価への加点（Rank に +5 など）は、この4モデルの後工程。今回はやらない。

## 9. 「有効度が高いほど結果が良いか」

仮にレース×俗説で effect（または後で作るスコア）が出せたら、holdout を分位する。

最初から 0-20-40-… の100点スケールにしない。**train の五分位**を境に freeze し、holdout に同じ境を使う。

各分位で:

- 該当馬の複勝残差・z・n
- 単勝ROI

理想: 上の分位ほど残差がプラスで、holdout でも単調。

単調でない（上の分位が弱い、真ん中だけ強い）なら 0〜100 表示は却下。条件表だけ残すか、機能ごと C。

採用閾値（画面の「🟢 採用」）も train で候補を3つ（例: 五分位の上、上2つ、z≥+2 かつ n≥200）に限り、holdout で1つ検証。決め打ちの 70点は使わない。

## 10. 切る軸（全体平均だけで判断しない）

各俗説について、最低限この切る軸で残差を出す（セルは n≥200 のみ判定）。

- 年
- 競馬場
- 芝 / ダート
- 距離帯
- 良 / 稍重 / 重不良
- 頭数（〜11 / 12〜14 / 15〜）
- 人気帯（1-3 / 4-5 / 6+）※穴帯と人気馬で符号が逆なら「全体有効」と書かない

「全体では無効、特定セルだけ有効」は②の主成果。ただしセル狩り禁止。**事前に上の軸だけ**。交互作用は「芝×内枠」「ダ×外枠」など、既存台帳にあるものに限る。

## 11. 成果物

スクリプト1本:

```text
python scripts/folklore_effectiveness_backtest.py
```

標準出力（UTF-8）と、任意で `data/folklore_effectiveness_summary.json`。

検証終了時に `repo/memory/verified_folklore_effectiveness.md` を書く。MEMORY.md への追記は結論が出てから。

### ① 全体表

俗説ごとの train / holdout 残差・ROI・年別符号・判定（全体有効 / 条件付き / 無効 / 標本不足）。

### ② 条件付きで残るもの

全体では否決、セルでは両窓プラス、の一覧。セル定義を固定して書く。

### ③ バイアス前後

B vs C vs D。D−C の holdout 残差と、同日2R未満で D が使えない割合。

### ④ 判定（どれか1つ）

- **A 実用化できそう** — 分位が holdout で単調。D が C を上回るか、C が B を安定して上回る。
- **B 条件限定で使えそう** — 一部セルは両窓で残るが、1本の総合点にはできない。
- **C 成立しない** — 有効度と実現効果に一貫した関係がない。機能却下。

### ⑤ 実装案（A または B のときだけ）

- 生データで十分か、0〜100 にするか
- 採用の言い方（🟢 今回見る / △ 参考 / ❌ 無視）。スコアを買い推奨に見せない
- 画面は俗説ランキングの外。予想エンジンにはまだ入れない
- 馬の Rank・妙味への接続は「別検証が必要」と明記するだけ

A/B でも、この工程では `core/folklore_lib.py` の点数や穴馬ハンターに足さない。

## 12. 判定の目安（既存俗説検証と同じ）

| 判定 | 目安 |
|---|---|
| 条件付きで残す | train と holdout の両方で残差の符号が同じ、holdout z の絶対値 ≥ 2、n≥200 |
| 全体では否決 | 全体残差がゼロ付近、または人気帯で符号が逆転 |
| 却下 | holdout で符号が逆、または分位が単調でない |

z の式は `gender_folklore_backtest` か `csv_data.resid_z` に合わせ、スクリプト内で混ぜない。

## 13. 作業順

1. 10俗説の該当フラグを CSV 上で作る（叩き2走目だけ履歴が要る）。
2. 全体の train/holdout 残差を出し、既存台帳と食い違わないか確認する。
3. 類似度 3案を train で1つに freeze。
4. モデル B/C をレース単位で計算。
5. 同日前レースのバイアスを足して D。
6. holdout で分位の単調性と D vs C を見る。
7. A/B/C を書いて memory に残す。

## 14. このアプリでの位置づけ（実装する段になったら）

買い決定（Rank / 穴馬ハンター / 3連単）とは別層。

- **妙味度** = この馬を買う価値があるか
- **俗説有効度** = このレースで、この俗説を信用していいか（レース環境のフィルター）

有効と出た俗説だけを、後工程で馬の評価に渡すかどうかを別検証する。
無効と出た俗説は、俗説ハンターのカタログには残してよいが、買い選定には使わない。

今の俗説シグナル（ハンター未捕捉の通知）とは別物。混ぜない。
