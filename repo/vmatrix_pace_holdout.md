# V Matrix Pace Holdout

Phase 2-1 調査（2026-09-07）。本番コード・UI・買い目・赤枠ルールは**変更なし**。

## 1. 対象データ

| 項目 | 値 |
|---|---|
| ペース分類比較レース数 | **14,764R** |
| 期間 | 2021–2025（JRA 場01–10） |
| V副次分析レース数 | **5,873R**（2024-01-01以降・同一条件） |
| pace BT 原データ規模 | ~22,721R（`scripts/pace_predict_backtest.py` 2021–25） |

**今回 14,764R となった理由（正解定義は同一）**

- 上記 pace BT と同じ **mae3f 距離×馬場 z** を正解に使用
- 追加フィルタ：JRA 10場のみ、`fetch_jv_profiles` 40%以上、mae3f 統計バケット存在
- 22,721R 全体との差は条件絞り込み。A/B は**同一レース集合**で比較

**正解定義（変更なし）**

- ソース：`races.mae3f`（前半3F・0.1秒単位）
- 標準化：`pace_predict_backtest.py` と同型 — `(surface, kyori//400)` バケット内 mean/sd
- `mae_z = -(mae3f - mean) / sd`（高い＝前半速い＝ハイ）
- 3択境界：`predict_pace_intensity` の**既存ラベル閾値**（新規最適化なし）
  - `mae_z >= 0.7` → ハイ
  - `mae_z <= -0.5` → スロー
  - それ以外 → ミドル

## 2. 比較方式

### A 現行（build_pace_context.pace）

| 段 | 内容 |
|---|---|
| 入力 | 出走馬 + `fetch_jv_profiles`（ten, ten_speed, corner, kyaku_pos, front3_rate 等） |
| 算出 | `build_pace_context()` → forward → `front_ratio` / `nige_umas` |
| ルール（既存・改変なし） | `front_ratio >= 0.40` または逃げ≥3 → **ハイ**；`front_ratio < 0.30` かつ逃げ≤1 → **スロー**；else **ミドル**；逃げ≥4 → **ミドル**（Lohengrin） |
| 出力 | `'スロー' \| 'ミドル' \| 'ハイ'` |
| 本番利用 | V radio 自動初期値（`app.py` `_pm_ctx['pace']`）、展開マップと**同一コンテキスト** |

### B ten_speed 系（predict_pace_intensity）

| 段 | 内容 |
|---|---|
| 入力 | 同一 `fetch_jv_profiles` の `ten_speed` |
| 算出 | 速い TOP3 平均 → 距離×馬場ノルム z（`data/pace_norms.json`） |
| 既存ラベル | z≥0.7 ハイ想定 / z≥0.2 ややハイ / z>-0.5 標準 / else スロー想定 |
| **V 3択への折りたたみ（既存ラベルのみ）** | ハイ想定→**ハイ** / スロー想定→**スロー** / ややハイ・標準→**ミドル** |
| 本番利用 | Scanner・3連複ヒント・`_pace_int_*` session。**V radio には未接続** |

**禁止事項の遵守**

- ten_speed を馬の縦座標には未使用（pos4 正本のまま）
- 閾値の事後調整・新 ML・確率化なし

## 4. V赤枠への影響

条件：馬座標は本番どおり **pos4 → ten → score**、馬場は **フラット固定**（ペース行の差のみ分離）。

| 指標 | A | B |
|---|---:|---:|
| A/B ペース一致率（=同一V行） | — | **36.16%** |
| V該当 Jaccard（A vs B） | — | **0.384** |
| V該当頭数 / レース | 1.25 | 1.39 |
| 複勝率（V該当馬・補助） | **24.35%** | 23.69% |
| 単ROI（V該当馬・補助） | -30.30% | -21.35% |

**ペースが変わったレース（3,788R）**

| | 複勝率（V該当馬平均） |
|---|---:|
| A ペース行 | 16.80% |
| B ペース行 | 16.59% |

**所見（V副作用）**

- A/B で **64% のレースがペース行が異なる** → V 赤枠行が頻繁にズレる
- V 該当馬集合の Jaccard 0.38 — pos4 整合（前 Phase）とは対照的に低い
- 複勝率は A が僅差で上（採用判断には使わない）
- 単ROI は双方 deeply negative（地図であり買いではない）

**整合性上の重要点**

- 展開マップと V は **`build_pace_context` を共有**（`_pm_ctx['pace']`）
- B のみ V に接続すると「展開マップ=スロー / V マトリクス=ハイ」の**同一レース内矛盾**が64%で発生

## 5. 結論

### 総合判定：**現行維持**

| 観点 | 判定 |
|---|---|
| ペース分類（mae3f 正解） | B が A を上回る（Acc +4.6pp, Macro F1 +5.0pp） |
| V 地図整合性 | **A 維持が妥当** — 展開マップと同一 `ctx.pace` を共有 |
| V 該当成績 | 補助指標。A 複勝率僅差上、ROI 双方マイナス |
| ten_speed 系の位置づけ | **既存配線を維持**（Scanner・3連複ヒント）。V 行には接続しない |

**用途別に言い換えると**

- **ペース予測単体**：B（ten_speed / `predict_pace_intensity`）は現行 A より holdout で改善 → 「②荒れ寄り / 本線向き」用途では**既に採用済み**
- **V ペース行**：B に差し替えると展開マップと地図が乖離 → **接続は保留（=現行 A 維持）**

Phase 2-2 以降で B を V に載せるなら、**展開マップ側のペース表示も同時に揃える**設計が先決。V だけ差し替えは非推奨。
