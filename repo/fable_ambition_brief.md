# Fableへの野心ブリーフ ―― 「不可能だが実現したらすごい」研究依頼

## 0. 前提（Fableはまずこれを読む）

このアプリのLTR（強適ランキング, LightGBM LambdaRank / 26特徴 / 60万件学習）の
2025 holdout成績:

| 指標 | 強適モデル | 人気だけのベースライン | 差 |
|---|---|---|---|
| win recall@7 | 93.6% | 92.7% | **+0.9pp** |
| top3 recall@7 | 88.1% | 88.0% | **+0.2pp** |

**結論: モデルは市場（人気）とほぼ同じ順序を出している。**
過去の自前検証（`memory/verified_*`）でも、単勝ROIは全オッズ帯で効率的、
PCI乖離・展開恩恵・巻き返し穴・当日バイアス順張りは全て「織込み済み or リーク」と判明済み。

→ **"予測精度を上げる"路線は飽和している。**
   依頼するのは「市場がどこで系統的に間違うか（＝残差）」の発掘のみ。

## 1. 絶対の縛り（これを破る提案は却下）

1. **評価は必ず jravan.db の 2025 holdout。** in-sample の数字は一切禁止。
2. **結果リーク禁止。** 脚質(kyakushitsu)・通過順・上がり順位は"レース後"の情報。
   過去に Stress Analyst 検証で、これらを使った"エッジ"が holdout で全滅した前例あり。
   事前に分かる情報だけで特徴量を作ること。
3. **エッジの主張は「複勝残差 z」または「recall@7 が val+test 両方で改善」でのみ認める。**
   単勝ROIプラスの主張は原則却下（市場効率が既定）。
4. **下記の"検証済み却下リスト"は再提案禁止**（交互作用として全く新しい形なら可）:
   - PCI乖離（単体・消去妙味ゼロ）
   - 次走巻き返し穴（comeback, ROI 66-68%）
   - 展開恩恵×人気薄（むしろ過剰人気）
   - 当日バイアス順張り（priced-in）
   - 末脚偏差×人気上位（人気薄限定でのみ機能）
   - 単勝期待値ゾーン（5-10倍にも+ROIポケット無し）
   - 前走圧勝馬を単勝軸に（過剰人気）／脚質を軸に（priced-in）
   - 補正タイム系俗説（5走前理論・SS×人気落ち）

## 2. 統一する北極星 ―― 「市場残差モデル」

全モジュールを **「勝ち馬予測器」→「市場残差予測器」** に振り直す。
市場は1着をほぼ完璧に当てる。エッジは"予測"でなく
**"市場implied確率と真の確率のズレが、大きく かつ out-of-sample で安定している ポケット"**
にしか存在しない。以下の各テーマは全部この残差の別の断面。

## 3. テーマ別「できたらすごい」＋Fableへの問い

### ① 強適ランキング ―― 3連単の"順序"残差
- **現状の壁:** recall@7 は飽和（1着が top7 に入る率は市場と同じ93.6%）。
  1着のピンポイントは市場が既に最適化済み。
- **できたらすごい:** top7 の中の**"順序"**、特に **2着・3着の並び**を市場より正確に。
  市場は1着は当てるが、2-3着の相対順序付けは甘い可能性がある（未検証）。
  ここに残差があれば **3連複・3連単の点数を劇的に絞れる**。
- **Fableへの問い:** recall@7 でなく **NDCG@3 / top3内ペア順序精度** を目的に、
  市場implied順序を holdout で上回る特徴は何か。
  候補軸: **馬主ID（未投入）**、**馬の系列トラジェクトリ形状**（前走スナップショットでなく
  「上昇/下降/ムラ」の時系列パターン）、厩舎キャンペーン意図。

### ② Vマトリクス / 末脚妙味アラート ―― FADE専用に振り切る
- **現状の壁:** Vマトリクスは「順張り＝死」「逆張り(外有利日×内枠1-3人気=複勝-4.6pp/z-3.8)」のみエッジ。
  末脚偏差も6人気以下限定。両方とも**軸でなく"消し/相手"ツール**が正体。
- **できたらすごい:** これらを「軸を強くする」用途から完全に切り離し、
  **危険人気馬の自動検出器**に純化。さらに当日バイアスを
  **"静的な結果集計"でなく"レース進行中の断層変化"から早期推定**できるか。
- **Fableへの問い:** 締切前オッズの時系列だけで、当日トラックバイアスの符号を
  発走前に推定できるか（現状は結果ベースで事後的）。

### ③＋⑤ 消去クロス改善 ＆ ボーダー3の廃止（統合課題）
- **背景:** 半分消去→3着内馬をこぼす→🛟ボーダーで1頭戻す、で
  取りこぼしを15%→10%に改善済み。だが**ボーダーは本来"消去の失敗の後始末"。
  理想は消去自体が3着内をこぼさないこと。**
- **できたらすごい:** 消去ルールの **precision（来ない馬を消す）× recall（3着内を残す）**
  フロンティアを、**ボーダー無しで現行のボーダー有り水準に**到達させる。
  ＝消去クロスの弱点フラグ組合せを、台帳が貯まる前でも holdout で学習化。
- **Fableへの問い:** どの弱点フラグ組合せが「3着内をこぼす偽陽性」か。
  jravan holdout で各フラグ組合せの precision/recall 曲線を描き、
  ボーダーに頼らず recall を保つ消去閾値を導けるか。

### ④ 調教師回収率 / 馬主データ ―― 新しいデータ軸
- **現状:** trainer_jyo_t3 は既にLTR投入済。厩舎"全体"勝率は織込み済み
  （当コース勝率🔴≥20%のみ妙味と判明）。→ 調教師回収率の追加投入は妙味薄の見込み。
- **本命は馬主。** 馬主IDは**未投入の新軸**。クラブ馬主/大馬主のデビュー配分・使い分けは
  市場が過小評価する可能性（未検証・却下リスト外）。
- **Fableへの問い:** 馬主ID（＋厩舎×馬主の交互作用）を auto_feature_loop に投入し、
  recall@7 が val+test 両方で改善するか。改善しなければ「馬主も織込み済み」として決着。

### ⑥ オッズ断層の強化 ―― 静的→時系列
- **現状:** odds_gap_anchors は比率2.0の**静的**な断層検出。
- **できたらすごい:** 断層の**時間変化**（締切直前の資金移動）。
  断層が締切前に「埋まる/深まる」方向から**"賢い金"の動きを検出**。
- **壁の注意:** 単勝ROIは効率的が既定。だが**断層×時系列**は未検証なので挑戦可。
- **Fableへの問い:** 締切N分前→締切時のオッズ変化ベクトルが、
  複勝残差に対して情報を持つか（静的断層に対して"増分"の情報)。

### ⑦ PCI強化 ―― ⚠地雷。交互作用に限定すれば余地あり
- **壁（重要）:** PCI乖離"単体"は消去妙味ゼロ、想定RPCI乖離は逆効果、
  動画が説く「PCI敗因分析→次走巻き返し穴」は **当アプリで二重に否定済み**
  （PCI乖離=priced-in ＋ 巻き返し穴=ROI66-68%）。**単体での再実装は禁止。**
- **唯一残る余地:** PCIを「軸補強」でなく **"コース形状適性マッチ"の相手選定**に限定。
  動画の O字コース(トップスピード維持)／U字コース(再加速・トルク) × 馬のPCI傾向の
  **交互作用**は未テスト。
- **Fableへの問い:** 「馬のPCI傾向 × コース形状」の交互作用が、
  **6人気以下の複勝残差**で holdout 有意か。単体PCIは否定済みなので
  **交互作用項のみ**が検証対象。有意でなければPCIは完全終了とする。

### ⑧ 波乱予測（コンピ大穴ロジックの再現）
- **元ネタ:** 日刊コンピ指数の大谷式 ―― コンピ1位≤79 かつ コンピ1位-3位差<15
  かつ 単勝30倍未満が10頭 = 大穴判定（黒丸）。コンピ導入自体は「似た機能あり」で不採用済み。
- **鍵:** このロジックは**コンピ無しで単勝オッズから等価再現できる**:
  - コンピ1位≤79（抜けた本命不在）→ **1番人気の単勝オッズが高い**
  - コンピ差<15（上位拮抗）→ **1-3番人気のオッズ分散が小さい**
  - 単勝30倍未満10頭（手広い）→ **"live"頭数が多い**
  ＝ **「オッズ・エントロピー／本命不在フラグ」**。
- **現状の荒れ条件:** ハンデ戦(+7.9pp/z5.2)とフルゲート16頭(z5.9)のみ独立エッジと判明済み。
  コンピ大穴は本質的にこの補完仮説。
- **Fableへの問い:** オッズ由来の本命不在フラグ
  `(1番人気≥N倍) & (top3オッズ分散<ε) & (30倍未満頭数≥10)` が、
  既存のハンデ/16頭フラグに対して**独立**の荒れ残差を持つか。
  持てば🔍Scannerへ追加。持たなければ「織込み済み」として却下。

### ⑨ MAGI回顧の閉ループ化
- **現状:** 合議ゲートは「妙味/見送り判定器」に転生済（独立エッジ3機=消去/単複乖離/末脚）。
- **できたらすごい:** 回顧が **"次の特徴量仮説"を自動生成して auto_feature_loop に投げる閉ループ**。
  人間インタビュー(おしゃべりルーム)からは俗説を隔離し、
  **検証可能な仮説だけを holdout に送る**弁別器を持たせる。

### ⑩ 集合知の乖離解消 ＋ エージェント増設設計
- **根因:** agent_forum の Ollama LLMペルソナは**検証済みエッジのgroundingが無く俗説を喋る**。
  record_result 台帳はあるが**重み付けに使われていない**（全員平等に合議）。
- **できたらすごい:** 各エージェントを**過去的中率(Brier)で重み付け**し、
  当たらないペルソナを**自動減衰／淘汰**。増設時は verified memory を知識注入し、
  俗説エージェントは隔離。＝**進化的（自然淘汰する）集合知**。
- **Fableへの問い:** N体のペルソナ予想を過去的中率で加重合議した確率が、
  単純平均や市場を holdout で上回るか。上回らなければ「LLM集合知は市場を超えない」で決着し、
  集合知は"予測"でなく"多様な却下理由の生成器"に再定義する。

## 5. Sonnet 5 実装カード（Fableが採用テーマごとに埋める / Sonnetはこれ1枚で着手）

各カードは以下の項目を埋めること。**推測でファイル名を書かず、§6 の配線マップに実在する
関数・モジュールのみ参照する。**

```
【エッジ名】 <例: オッズ本命不在フラグ(荒れ)>
【検証決着】 holdoutの数値を必ず1行で。例: 6人気以下複勝残差 +X.Xpp / z+X.X (2025 holdout, n=____)
            ＋ リーク無し確認（使用特徴が全て発走前情報である旨）
【種別】     予測特徴量 / 妙味・荒れフラグ / トラックバイアス / 消去・相手 / 資金 / 集合知 / MAGI のどれか
【配線先】   §6のどのモジュール・関数に、どう足すか（既存シグネチャは変更しない＝追加関数で）
【新規ファイル】 core/xxx.py or scripts/xxx.py（可逆性優先＝まず新規で作る）
【検証スクリプト】 scripts/<name>_backtest.py（Sonnetが配線前に再現実行して数値一致を確認する）
【app.py 配線点】 どのnavセクション（🔍Race Scanner / 🧹消去フィルター / 💰BetSync 等）に出すか
【smoke.py 追加】 tests/smoke.py に足す最小チェック（import可能・関数が期待型を返す 等）
【ロールバック】 配線を1コミットで戻せる手順（新規ファイル削除＋app.pyの数行revert 等）
【非目標】   このカードで"やらない"こと（scope固定。既存モデル再学習の要否も明記）
```

Sonnetへの遂行ルール（各カード共通・カード本文には再掲不要、Sonnetは§6を読む）:
1. **検証を配線より先に。** 新エッジは必ず先に `scripts/<name>_backtest.py` を書き、
   jravan.db 2025 holdout の数値を出す。カード記載値と一致しなければ配線せず差分を報告。
2. **holdoutで有意でなければ配線しない**（却下して理由を報告。これは失敗でなく正しい結果）。
3. 変更後 `python tests/smoke.py` を実行し終了コード0を確認、`FEATURE_STATUS.md` を更新。

## 6. Sonnet 5 が必要とするプロジェクト前提（Fableはカードをこれに合わせる）

### 環境・絶対規約（CLAUDE.md準拠・破ると却下）
- Python 3.13 / Streamlit / Windows。**文字コードは常にUTF-8（BOMなし）**。
- **既存の関数シグネチャを変更しない**（機能追加は新規関数で）。
- **requirements.txt に無いライブラリを追加しない**。
- **スクレイピングは必ず `core/scraper.py: fetch_robust_html`**（requests直叩きはボット検知でブロック）。
- スクレイピング処理をOCRに置き換えない（OCRはEasyOCR固定）。
- **結果リーク禁止**（kyakushitsu / 通過順 / 上がり順位 は発走後情報。特徴量に使わない）。

### 正解データ・評価
- `data/jravan.db` … 検証の正解データ（2025を holdout に使う）。in-sample数値は不可。
- `data/ltr_meta.json` … LTR現行26特徴と holdout metrics（win/top3 recall@7）。

### 配線マップ（エッジ種別 → 触る場所）
| 種別 | 配線先 | 備考 |
|---|---|---|
| **予測特徴量** | `scripts/auto_feature_search.py` で探索 → 通れば `scripts/build_ltr_model.py`の特徴リスト＋`core/ltr_ranker.py`の特徴生成に追加 | **LTRモデル本体は auto_feature_search が val+test 両改善を出すまで触らない** |
| **妙味・荒れフラグ** | `core/value_scanner.py`（race_value_score / trio_lean / race_skip_reasons）＋ app.py `🔍Race Scanner` | オッズ本命不在フラグ(⑧)はここ |
| **トラックバイアス/枠順/当日** | `core/track_bias.py` | **NARは場コードでゲート必須**（JRA検証値を地方に出さない） |
| **消去・相手絞り** | `core/elim_cross.py` ＋ `core/elim_reasons.py`、app.py `🧹消去フィルター` | ボーダー廃止(③⑤)はここ |
| **資金・台帳** | `core/money.py`（Ledgerクラス） | 単勝ROI主張は原則却下 |
| **集合知** | `core/agent_forum.py`（save_prediction / record_result 台帳を重みに使う） | ⑩の加重合議 |
| **MAGI** | `core/magi_consensus.py` / `core/magi_chat.py` / `core/magi_retrospective.py` | ⑨の閉ループ |

### QAゲート（既存・project_qa_harness）
- `FEATURE_STATUS.md` … 機能の正準表。実装後に必ず更新。
- `tests/smoke.py` … pytest不要・終了コード=失敗数。新エッジのimport/型チェックを追加し、緑を確認。

### 可逆性
- まず新規ファイルで作り、既存(app.py等)への配線は最小diff。1コミットで戻せる形にする。
