## 1. なぜ別レイヤーか（構造的事実）

| 既存系 | 新馬戦での状態 | 理由 |
|--------|----------------|------|
| 📊 強適 Ranking Table | **機能しない** | 過去走・能力比較が入力。新馬は過去走ゼロ |
| 展開MAP / pos4 / Vエリア | **機能しない** | `fetch_jv_profiles` が空（現行の「データなし」表示は正しい動作） |
| 🏇 J5（騎手係数込み総合スコア） | **使える** | 騎手・厩舎の過去成績ベース。馬の過去走に依存しない |
| 黄金ライン（全レース版） | **使える** | 同上 |

**評価構造の転換（設計の中核）:**

```text
通常レース:  馬能力評価 ↑↑   人的情報 ↑
新馬戦:      馬能力評価 ↓↓   人的情報 ↑↑  + 市場基礎確率
```

新馬戦では「誰が乗るか・誰が管理するか・その人たちの勝負度合い」と「新馬戦という市場の基礎特性」が主な情報源になる。

## 3. Phase 1 — 新馬戦モード表示仕様（スコアなし・表示のみ）→ **実装済み（2026-09-07）**

実装:
- `core/maiden_mode.py` … 表示集約レイヤー（判定ロジックは `core/jockey_jv.py` に委譲）
- `app.py` … SRA 妙味度ブロック直後に expander「🆕 新馬戦モード」を追加
- `core/scraper.py` … `extract_trainer_id()` 追加。出馬表の `/trainer/XXXXX/` から
  調教師コードを直接取得（netkeiba ID = JRA 調教師コードを実ページ照合済: 01105=須貝尚介）。
  これにより **未デビュー馬でも黄金ライン・厩舎成績が出る**（馬名解決 `resolve_horse` は
  デビュー前では効かないため必須の経路だった）
- `tests/test_maiden_mode.py` … 契約テスト（判定基準/必須キー/禁止キー/平易ラベル/固定文）
- 実レース出力確認: `scripts/debug/_maiden_live_check.py`
  （2026年 阪神芝1600 新馬で M.デムーロ騎乗馬に 🥇🥇 が正しく付くことを確認）

### 3.1 起動条件

- 既存の新馬検出（`meta['class']` に「新馬」）で **新馬戦モード** に切替
- 過去走依存セクション（強適/展開MAP/Vエリア/新聞の隊列図）は **非表示または「新馬戦のため対象外」プレースホルダ** に置換
  - 「データなし」で終わらせず、「このレースは下の専用情報で見る」と誘導する

### 3.2 表示ブロック（案）

```text

🆕 新馬戦モード（過去走がないため専用表示）

        ⭐騎手×厩舎の相性: あり（過去の全レース実績）
```

### 3.3 表示ルール（確定）

1. **数字には必ず平易な説明を添える**（USM→「期待に応える力」等。既存 J5 の言い換え規約に倣う）
2. **⭐黄金ラインは全レース版の実績であることを必ず併記**（「新馬戦での特別な相性」と誤認させない）
3. **生まれ月・兄弟・新馬限定コンビは出さない**（§2❌）
4. **順位づけ・合成スコア・◎○▲印は Phase 1 では付けない**（材料の並列表示のみ）
5. 買い目・Rank/VH・合議・playbook には **一切接続しない**

## 4. Maiden Score の変数設計（Phase 2 候補）

合成は **Phase 2 の holdout を通ったものだけ**。候補変数と現時点の証拠状態:

| # | 候補変数 | 方向 | 証拠状態 | ライブ取得 |
|---|----------|------|----------|------------|
| V1 | J5 騎手係数（mult） | 高いほど◎ | ~~検証済み（全レース）~~ → **新馬では残差蒸発・Step A 不採用**（z+0.88・非単調） | ✅ 既存 |
| V2 | 黄金ライン区分（全レース版 40/35/30%） | 高いほど◎ | 検証済み（全レース）→ **新馬では n 不足で Step A 不採用**（+3.63pp も CI 跨ぎ） | ✅ 既存 |
| V3 | 厩舎ランク＋当コース勝率（縮小済み） | 高いほど◎ | **新馬で唯一 Step A 採用**（+0.94pp・z+2.03・単調。ただし効果量小） | ✅ 既存 |
| V4 | 人気順位 | 上位ほど基礎勝率高い | **今回実測**（新馬1人気 35.0%） | ✅ オッズ |
| V5 | ~~遅デビュー（35ヶ月+）~~ | ~~減点方向~~ | **破棄確定（2023前向き再検証 z=−1.57）** | — |
| V6 | 調教短評トーン（＋/・/－） | 参考 | **後ろ向き検証不可**（oikiri はライブ取得のみ・DB 蓄積なし。JV `training` 表も 2025-06〜の1年窓で holdout 期間を欠く → 前向き収集が先） | ⚠ 要蓄積 |
| V7 | 血統（父の新馬実績等） | 候補止まり | 人気薄×父は |z|<1.7 で却下済み。**入れるなら別BT必須** | ✅ 既存 |

**組み合わせ方の事前固定（合成ルール）:**

- 機械学習・重回帰・最適重み探索は **使わない**
- 許容するのは **透明な加算/段階ルール**のみ（例: 各変数を3段階化→合計点）
- 重み・段階閾値は **train期間で一度だけ決めて凍結** → holdout 一度勝負
- 合成前に **単変数ごとの人気統制後残差** を全て報告し、残差が有意な変数だけ合成候補にする（合成の前段ゲート）

## 6. Phase 2 — holdout 設計（事前固定）

### 6.1 母集団・正解

| 項目 | 定義 |
|------|------|
| 対象 | 各馬の初出走（デビュー戦）。JRA場01-10、芝/ダート、障害除外（今回の検証と同じ定義） |
| 正解 | 着順（1着/2着/3着）、単勝・複勝払戻 |
| ベースライン | 人気別 勝率/複勝率（train凍結）。**人気統制後の残差が主指標** |
| 分割 | train 〜2017 / holdout 2018–2022（今回の検証と同一枠でOKなのは§4の単変数まで。合成スコアは §6.3 の通り） |

### 6.2 成功条件（事前固定）

| 条件 | 閾値 |
|------|------|
| 合成スコア top1 の複勝残差 | **+3pp 以上 かつ bootstrap 95%CI が 0 を跨がない** |
| top3 内占有率の単調性 | スコア上位→下位で複勝残差が単調減少 |
| 単勝 ROI | ベースライン（同人気帯）を悪化させないこと（地図用途でも確認） |

### 6.3 データスヌーピング防止ルール

- §4 V5（遅デビュー）は 2018–2022 で発見済み → **同じ期間で再検証しない**。2023年分（birth カバレッジ 76.6%・欠損バイアスを併記）または **2026年以降の前向き収集** で確認するまで、スコアにも表示にも入れない
- 単変数の新規採用は train 期間のみで探索 → holdout は一度だけ
- Phase 2 の脚本作成時に `scripts/maiden_score_backtest.py`（仮）として新規作成。既存BTの流用・改変はしない

### 6.4 V5 専用の再検証ミニ設計 → **実施済み・破棄**

| 項目 | 内容 |
|------|------|
| 定義（事前固定） | デビュー時月齢 ≥ 35ヶ月（発見時と同じ閾値をそのまま使用） |
| 期間 | 2023年デビュー馬（birth カバレッジ 76.6%・欠損バイアス併記） |
| 判定ルール | 複勝残差 < 0 かつ z ≤ −2.0 で生存 |
| **結果（2026-09-07）** | **−2.12pp / z=−1.57 → ゲート未達・破棄**。方向は再現（CI[−3.95,−0.25]）したが事前固定ルールに従い採用しない。脚本: `scripts/maiden_late_debut_recheck.py` |

## 7. Phase 3-4 — 独立パスと評価指標

```text
新馬戦検出
   ↓
新馬戦モード表示（Phase 1）
   ↓
Maiden Score（Phase 2 通過後のみ）
   ↓
馬券候補（Phase 3: 通常エンジンとは完全分離。合議・Rank/VH には流さない）
   ↓
評価（Phase 4）: 的中率 / ROI / Hit3 / 1着率 / 2着率 / 3着率
```

**既存エンジン汚染防止（確定）:**

- Maiden Score は通常レースのスコア・消去・買い目に **混入させない**
- 逆方向も同じ（通常レースに新馬モードの変数を持ち込まない）
- playbook への記録は「新馬モード」タグを必須化し、実績を通常馬券と分離集計する

## 9. 禁止事項（本設計のガードレール）

1. 早生まれ・兄弟・新馬限定黄金ライン・調教タイムを **妙味材料として表示・加点しない**（§2❌）
2. Maiden Score を holdout なしで本番合成しない
3. 通常レースのスコアリング・消去・買い目・Rank/VH に Maiden 変数を入れない
4. 新馬戦で展開MAP/Vエリア/強適を **無理に生成しない**（空表示のまま専用モードへ誘導）
5. 動画・外部理論の数値は **再現検証なしに UI に出さない**
6. UI の新しい指標には平易な言い換えを必須とする（`plain-label-check` 準拠）
