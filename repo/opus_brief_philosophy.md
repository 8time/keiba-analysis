## 依頼（人間からの要望・原文の意図）
「開発者（AI）の思考」で選んだ馬・組み合わせをSRA（🏠 Single Race Analysis）内に表示したい。
毎レース、その思考プロセスで選んだ結論を出す。思考プロセスの各ステップは細かく設定できるようにする。
併せて、この予想の意思決定フローを**モデル非依存のドキュメント**として言語化し、
Fableが使えなくてもSonnet/Opusが同じ順序・同じ基準で予想を再現できるようにする。

## 大原則（この案件の背骨）
- **思考法はLLMの一般知識から生成しない。** このプロジェクトには2年分のバックテストで
  「効く」と検証されたエッジと「効かない」と反証された俗説の台帳がある
  （`C:\Users\kimnhaty\.claude\projects\c--Users-kimnhaty--gemini-antigravity-scratch-keiba-analysis\memory\` 配下、
  索引=`MEMORY.md`）。**思考法ドキュメントはこの検証済み結論の編纂**であり、創作ではない。
- 一般的な競馬理論（展開読み・脚質・ペース恩恵・EV>100で買い等）は
  ほぼすべて検証済みで**織込み済み（priced-in）と反証されている**。禁止リスト参照。
- 思考エンジン②は**LLM呼び出しを含まない決定的なルールエンジン**として実装する
  （毎レースLLMに考えさせる方式は再現性・コスト・俗説再発明リスクで却下済み）。

## フェーズ② 思考エンジン実装（SRA配線＋設定）

### 成果物
1. `core/philosophy.py`（新規）— 思考エンジン。
2. SRA内に「🧠 開発者の思考」セクション（`app.py`）。
3. `philosophy.json`（ルート・新規）— ステップ設定の永続化。
4. `FEATURE_STATUS.md` への行追加＋`tests/smoke.py` が通ること。

### core/philosophy.py の設計
- 入力: SRAが既に計算済みのデータ（強適テーブルDataFrame・オッズ・consensus_viewの合議結果・
  danger_gateの判定・value_scannerのレジーム）。**再スクレイピング・再計算はしない。**
  既存モジュールの結果を受け取って思考フローとして編成するだけの薄い層にする。
- 出力: `ThinkingResult` 相当のdict —
  - `steps`: ステップごとの `{name, verdict, reasons: [平易な日本語の理由文], skipped}`
  - `final`: `{本命, 相手, 穴, 消し, 買い目 or 見送り, 見送り理由}`
- 各ステップは純関数にし、`philosophy.json` の設定で ON/OFF・強度を切替。

### philosophy.json（設定スキーマ案）
```json
{
  "steps": {
    "race_filter":   {"enabled": true, "mode": "標準"},
    "elimination":   {"enabled": true, "mode": "標準"},
    "danger_check":  {"enabled": true, "mode": "標準"},
    "value_hunt":    {"enabled": true, "mode": "標準"},
    "axis_support":  {"enabled": true, "mode": "標準"},
    "bet_build":     {"enabled": true, "mode": "標準"},
    "devil_advocate":{"enabled": true, "mode": "標準"}
  }
}
```
- `mode` は **「厳しめ/標準/ゆるめ」の3値のみ**（連続スライダー禁止。理由は下記UI方針）。
  各モードが具体的にどの閾値に対応するかは①ドキュメントの基準から引く。

### SRA表示（app.py）
- 配置: 統合ビュー（app.py 7028行付近「🧩 統合ビュー」）の**直後**に expander
  「🧠 開発者の思考（この予想の考え方）」を追加。
- 中身: ステップごとに1行の結論＋理由を平易な日本語で。例:
  - 「① レース選別: このレースは荒れ予報68%（本命不在型）→ 穴寄りで考えます」
  - 「② 除外: 7番・12番を消し（来にくさフラグが3個重複）」
  - 「⑥ 反対役: 1番人気に危険材料2つ（ガラス人気・断層直下）→ 本命の信頼度は低め」
- 最後に「この思考で選んだ馬・組み合わせ」を明示（consensus_viewの合議結果＋trio_engineの
  買い目を思考の結論として再掲。**新しい予測ロジックは作らない**）。
- 設定UI: expander内 or サイドバーに、ステップごとの ON/OFF チェックボックス＋
  「厳しめ/標準/ゆるめ」プルダウン。変更は `philosophy.json` に保存。

### UIラベル方針（厳守 — ユーザーは競馬・EV計算の初心者を自認）
- 略語（EV/LTR/combo/z等）を出すときは平易な言い換えかツールチップを必ず併記。
- **連続値メーター/スライダー禁止**。設定はすべて離散的な選択式（3値プルダウン/チェックボックス）。
- 理由文は「〜のため」「〜が3個重複」のような日本語文。数値を出すなら意味を添える。

### ②の完了条件
- 消去/危険/妙味/合議の判定が**既存表示（統合ビュー・消し候補・danger警告）と矛盾しない**こと
  （同じ関数の結果を使っていれば自動的に満たされる。独自再実装をしないこと）。
- `philosophy.json` の ON/OFF が表示に反映される（OFFのステップは「スキップ」と表示）。
- `tests/smoke.py` が終了コード0。`FEATURE_STATUS.md` に本機能の行を追加。
- 動作確認はStreamlitの**完全再起動**（Ctrl+C→`streamlit run app.py`）で行う
  （ブラウザReload/Rerunではモジュールキャッシュで反映されない）。
