## 依頼の背景（人間からの要望・原文の意図）
ユーザーが実際に発行したPDF(函館5R・14頭収録)を見て3点の指摘:
1. ページ内に不自然な空白/隙間がある(添付PDF1ページ目、テーブル10行の後の余白)。
2. 100円でコンビニプリント(ネットプリント等)して売る想定。**A3縦・カラー**なら
   A4横2枚分の情報量が1枚に収まるはずなので、その仕様に寄せたい。
3. 図(展開図・隊列の視覚化)が1つも無い。無い方がいいのか、あった方がいいのか
   判断してほしい → **1つだけ追加する方針で合意**(展開・隊列のレーン図)。

## 技術的な手がかり(調査済み・Opusは実レンダリングで裏取りしてから着手)

### ①の手がかり: ページサイズの二重管理
`core/newspaper.py` には**ページサイズを決める場所が2つ**ある:
- HTML内の `@page {{ size: {page_size}; margin: 8mm 7mm 10mm 7mm; }}`
  (関数内、`page_size = 'A4 landscape' if landscape else 'A4 portrait'` で計算・
  約1898-1900行)
- `html_to_pdf()` 関数がPlaywrightの `page.pdf(format='A4', landscape=bool(landscape), ...)`
  を呼ぶ箇所(約1998-2010行)

現状は両方"A4"で一致しているため矛盾が表面化していないが、**Chromiumの印刷エンジンが
実際にどちらを優先するか(@page CSSかPlaywrightのformatパラメータか)は検証されていない**。
②でA3に変更する際、この2箇所を**両方揃えて変更しないと**、サイズ不一致で
予期しないレイアウト崩れ(それこそ"変な空白"の再発)が起きる。

また、テーブル行の改ページ制御は:
```
table.kt {{ ... {'page-break-inside: avoid;' if o.get('keep_table', True) else ''} }}
table.kt tr {{ page-break-inside: avoid; }}
```
`<tr>`に`page-break-inside: avoid`が付いているため、**1行がページ末尾に収まりきらないと、
その行はページ末尾に空白を残したまま丸ごと次ページへ送られる**。行の高さは
血統セル(2行になりうる)・騎手力/乗替セル(`<br>`で2行になる・今セッションで追加した
折り返し)等で不揃いなため、この「行単位の送り」が空白の直接原因である可能性が高い
(添付PDFで10行目の後に隙間があるのはこのパターンに合致する)。
**ただし断定はせず、実際にPDFを開いて隙間の正確な位置とサイズを確認してから
修正すること。**

### ②の技術的な鍵: A3縦 = A4横×2段
A3縦(297×420mm)の幅はA4横(297×210mm)の幅と同一で、**高さがちょうど2倍**。
つまり「A3縦1枚 = A4横2枚を上下に積んだもの」は寸法上ほぼ正確に成立する。
既存CSSは%ベース(幅32.8%のexbox等)が多く方向非依存の設計なので、
`page_size`と`html_to_pdf`の両方を`'A3 portrait'`/`format='A3', landscape=False`に
揃えるだけで、**印刷可能領域が単純に倍になり、今まで2ページに割れていた内容が
1ページに収まる可能性が高い**。ただしmm固定値(`min-height: 5mm`等)や
`@page`のmargin値がA4基準で調整されている箇所は、A3で余白比率が変わらないか
確認すること。

### ③の技術的な鍵: 展開図に使えるデータは既にある
`_pace_html(race_id, records)` が読む `pc.get('pos4')` は `{umaban: 0.0〜1.0}` の
通過位置比率(0=最前・1=最後方)を持っている。**この数値をそのままSVG/HTMLの
横棒(レーン)図に変換すれば、新しい予測ロジックを1行も足さずに視覚化できる。**

## フェーズ① 空白/改ページ原因の特定と修正

### 手順(必須・省略不可)
1. `scripts/batch_track_record.py` 等で使っている既存レース(または
   `tests/smoke.py` のテスト用スナップショット)を使い、**実際に
   `build_newspaper_html` → `html_to_pdf` を実行してPDFを生成**する。
2. 生成したPDFを開く(またはPlaywrightで各ページをPNGスクリーンショットして
   `repo/`配下等に保存し確認)。添付PDFと同じ現象(テーブル行の後の空白)が
   再現するか確認。
3. 再現したら、DevTools相当の方法(HTML単体をブラウザで開いて印刷プレビュー確認、
   または該当`<tr>`の実測高さをPythonから逆算)で「どの行が次ページに送られて
   空白ができているか」を特定する。
4. 原因が「不揃いな行高+`page-break-inside: avoid`」であれば、対策候補
   (Opusが実測結果を見て選ぶ): (a) 行の最小/最大高さを揃えて予測しやすくする、
   (b) ページ末尾の余白許容量を計算し、入りきらない行数を事前に数えて
   意図的に早めに`.pbb`(page-break-before)を挿入する、(c) ②のA3化で
   そもそも空白が解消されるならそちらを優先し①では軽微な調整に留める。
5. **修正後、再度PDFを生成して目視確認**してから完了報告。

### 承認ゲート
Before/After のPDF(またはページスクリーンショット)をユーザーに提示。

## フェーズ② A3縦1枚・コンビニプリント対応

### 成果物
1. `DEFAULT_OPTS['orientation']` の選択肢に `'a3_portrait'` を追加
   (既存の`'landscape'`/`'portrait'`と共存。既定値は変えない=A4横のまま)。
2. `build_newspaper_html()` 内の `page_size` 計算と、`html_to_pdf()` の
   `format`/`landscape`引数を、新しいorientation値に応じて**両方揃えて**
   `'A3 portrait'` / `format='A3', landscape=False` になるよう分岐追加。
3. `pages/newspaper_pub.py` の用紙選択ラジオボタンに
   「A3 縦（コンビニ印刷向け・A4横2枚分/1枚に収録）」を追加。
   選択時のcaptionで「セブンイレブン/ファミリーマート等のネットプリントで
   A3カラー印刷に対応した設定」である旨を明記(実際に主要コンビニ複合機の
   A3カラー印刷対応状況・料金は変動するため、**断定的な金額表示はしない**
   ＝「印刷店舗により料金は異なります」等の注記を入れる)。
4. フォントサイズ(`font_pt`既定6.8)がA3縦でも可読か確認。A3は物理的に大きい紙
   なので、A4横と同じpt数でも実寸の文字は大きくなる(良い方向)が、逆に
   情報量を増やしすぎて結局読みにくくならないか、実際に印刷(または原寸大PDF
   表示)で確認する。

### テスト
- `tests/smoke.py` に、`build_newspaper_html(race_ids, {'orientation': 'a3_portrait'})`
  がエラーなくHTMLを生成し、`@page`に`A3 portrait`が含まれることを確認するテスト追加。
- `html_to_pdf`のformat分岐をユニットテスト化(PDF生成自体はPlaywright依存で
  重いため、format/landscape引数の分岐ロジックのみ関数分離してテスト可能にする)。

### 承認ゲート
A3縦で実際に生成したPDFをユーザーに提示し、①の空白問題がA3化で解消したか/
新たな余白問題が出ていないかを確認してから③へ。

## フェーズ③ 展開図(隊列レーン図)の新設

### 目的
`_pace_html`が持つテキストの隊列情報(「(前) 3 9 5 6｜4 13 12 8 14 11 2 1｜10 7 (後)」)を、
**同じデータのまま**横棒レーン図として視覚化する。新しい予測ロジックは作らない
(既存`pos4`の並び替え表示のみ)。

### 成果物
1. `core/newspaper.py` に `_pace_diagram_svg(pos4, labels)` を追加。
   - 横1本のレーンに、各馬番を`pos4`の値(0=最前〜1=最後方)に応じて
     左から右へ配置したSVG(またはインラインHTML+CSSのdiv配置)を生成。
   - 印刷対応のためJSは使わず、静的SVG(`<svg>`要素を文字列で組み立てる)。
   - 密集(数値が近い馬が多い)場合に馬番ラベルが重ならないよう、上下に
     ジグザグ配置する等の簡易な重なり回避を入れる(装飾のみ・判定ロジックではない)。
2. `_pace_html`の出力に、この図をテキストの隊列表現と併記する形で追加
   (テキストは残す。図はテキストの補助であり置き換えではない)。
3. section キーは追加しない(`_pace_html`の中身が増えるだけなので`pace`セクションの
   既存ON/OFFがそのまま図の表示/非表示も制御する)。

### 承認ゲート
実際にPDF化した図をユーザーに提示。「多すぎず・見やすいか」「密集レースで
潰れて読めなくなっていないか」を確認してもらう。良ければ完了、崩れる場合は
密集回避ロジックを調整。

  matplotlib等の画像ラスタライズライブラリは使わない=印刷解像度と依存追加を避ける)。

  レイアウト系の不具合はコードレビューだけでは再現・解消の確認ができない。
