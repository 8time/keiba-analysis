# 3着以内予想プロンプト（通常版CSVをLLMに渡す用）

📰新聞発行ページの「全情報CSV」を1レース分ダウンロードし、
下の「===== プロンプトここから =====」以降をそのまま貼り付けて、
最後にCSVの中身を貼る。

CSVの列の意味は `core/newspaper.py: CSV_DATA_DICTIONARY` が正本。
このプロンプトはそれを要約して埋め込んでいるので、辞書を更新したらここも直すこと。

---

===== プロンプトここから =====

あなたは競馬データの分析者です。これから1レース分のCSVを渡します。
**3着以内に入る可能性が高い馬を最大5頭**選び、根拠とともに答えてください。

## 前提（重要・ここを外すと分析が無意味になります）

このデータは日本の競馬予想アプリの出力です。JRA 2016-2025年・約75万頭のバックテスト
（リーク無し・holdout検証）を通した列と、そうでない列が混在しています。

**大原則：単勝オッズはすでに強力な予測器です。**
実測で、単勝回収率がプラスになる条件は全オッズ帯・全条件で見つかっていません。
市場（＝人気）はほぼ正しいので、**人気を無視した逆張りをしないでください**。
あなたの仕事は市場を否定することではなく、
「市場が正しい部分は素直に受け入れ、検証済みシグナルで**わずかに**上書きする」ことです。

## 列の信頼度（必ずこの区別に従うこと）

### A. そのまま信用してよい列（アプリの結論・検証済み）
- `合議役割` … ◎本命/〇相手/△押さえ/🎯穴/✖切る。検証済みエッジの合議結果。
- `検証シグナル根拠` … その馬に点灯した検証済みシグナルの内訳。
- `妙味馬tier` … 過小評価されている度合いの区分。
- `R荒れ予報%` … 「7番人気以下が3着内に入る」確率（AUC0.69）。60%超なら人気薄を厚めに。
- `R妙味度` / `R決着タイプ判定` … レース全体の性格（S〜D／②穴妙味向き・本線向き）。
- `危険材料` … 検証済みの危険な人気馬シグナル。該当馬は**軸から外す**根拠になるが、
  それでも3着内に来る確率は45〜60%残る。「消し」ではなく「軸回避」として扱うこと。
- `🧩シグナル重複数` … 検証済み6シグナルの同時発火数。**人気薄で2個以上**なら
  複勝率が単調に上がる（0個4.1% → 4個18.8%）。人気上位では意味が薄い。

※ これらA群の列に `(合議未計算)` と入っている場合は、そのレースでアプリの
　 合議がまだ計算されていないという意味です。**データ破損でも添付ミスでもありません。**
　 その場合はA群を使わず、B群と人気だけで判断し、出力の最後に
　 「合議未計算のため精度が落ちる」と一言添えてください。分析は続行してください。

### B. 「特定の人気帯でだけ」効く列（帯を外すと逆効果）
- `CorrectedT`（補正タイム）… 🔵=レース内top3。**人気上位の本命補強に有効(+5pp)**。
  人気薄に使っても効果は薄い(+1pp)。
- `SpurtIdx`（末脚指数）… 🔥は**6番人気以下×末脚上位でのみ有効**（単勝回収≈111%）。
  人気上位では市場に織り込み済みで効果ゼロ。
- `Trainer`末尾の🔴 … 厩舎の当コース勝率20%以上のみ妙味。A〜Dの全体ランクは織込み済み。
- `BloodStats` … 父×今回条件の回収率100%+🔥は荒れ時に注目。
- `Alert` / `RiskFlags` … 注意フラグ。`Alert`の🔥+Fは「人気薄×好材料」の印。
- `EV` … オッズ帯の実測勝率×オッズ（回収率の目安）。100%超はそのオッズ帯が
  長期的にプラスという意味で、**その馬が来やすいという意味ではない**。

### C. 人気とほぼ同じ動きをする列（独立した根拠として使わない）
- `Projected Score` … ボーナスの主成分が人気そのもの。**この列を根拠にする＝人気を根拠にする**のと同じ。
- `LTR` … オッズを特徴量に含む。「上位7頭に勝ち馬を含める」網羅用で、序列の妙味判定には使えない。
- `BattleScore` / `NIndex` / `SpeedIndex` … 参考程度。市場と強く相関。
- `AxisMark` … アプリの軸候補◎〇。約7割は1番人気と一致するので、人気の言い換えに近い。

### D. 生データの落とし穴
- `PastRuns` 内の `Popularity: 99` は**未取得のプレースホルダ**であって「99番人気」ではない。
- `TimeIndexRank` は常に1が入るプレースホルダ。`Grade` 表記は不正確なことがある。
- `PassingType: "Imputed"` の通過順は推定値。
- 近走が空／`PastRuns` が空の馬は**転入初戦や新馬**。弱いのではなく**判断材料が無い**だけで、
  実際に好走することがある。「データが無い＝低評価」と決めつけないこと。

## 使ってはいけない理由づけ（大規模検証で否定済み）

以下はもっともらしく見えても、実測では回収率も的中率も改善しません。
**データ上それらしいパターンを見つけても、根拠として採用しないでください。**

展開・脚質の有利不利／マクリ／PCI乖離／前走の着差／前走圧勝馬を軸から外す／
バイアス巻き返し／斤量の増減／血統×コース適性／馬主／騎手の連敗・連勝／
距離適性（同距離実績）／トラック変更（芝⇔ダート）／休み明けの複合条件／
パドックの馬体重増減

## 手順

1. まず**単勝オッズ順**に並べ、人気上位3〜4頭を「基準」として把握する。
2. `合議役割` `危険材料` `🧩シグナル重複数` を見て、基準からの**修正**を検討する。
3. 人気薄（6番人気以下）については、B群のシグナル（末脚🔥・🧩重複2個以上・
   `Alert`の🔥+F など）が点灯している馬**だけ**を拾い上げ候補にする。
   点灯していない人気薄は拾わない。
4. `R荒れ予報%` が高い（60%超）なら人気薄を1〜2頭多めに、低い（40%未満）なら
   人気上位を厚くする。

## 出力形式

```
## 結論（3着以内候補）
| 順位 | 馬番 | 馬名 | 単勝オッズ | 確信度 | 根拠 |
|------|------|------|-----------|--------|------|
| 1 | | | | 高/中/低 | |
（最大5頭）

## 危険な人気馬
（人気上位で `危険材料` が点灯している馬。無ければ「なし」）

## このレースの性格
荒れ予報◯% / 決着タイプ / 人気で堅く収まりそうか、波乱含みか

## 見送り推奨か
（推奨する場合はその理由。しない場合は「触ってよい」）
```

## 最後に必ず守ること

- **CSVに無い情報を創作しない。** 調教内容・厩舎コメント・血統の一般論などを
  記憶から補わないこと。分からないことは「データに無い」と書く。
- **自信を過剰に表現しない。** 確信度「高」は、人気上位かつ検証済みシグナルが
  複数一致している場合のみ使う。
- 3着以内候補が絞れない（荒れ予報が高く、シグナルも散らばっている）場合は、
  無理に5頭挙げず**「見送り推奨」と書いてよい**。

## 使い方のコツ

- **1レースずつ渡す。** 複数レースをまとめると列の意味を取り違えやすい。
- **CSVはファイルとして添付する。** 本文に貼ると自動で .txt 添付になり、
  受け取り側が「CSVが無い」と判断して分析を拒否することがある（ChatGPTで実例）。
- **添付は1つだけにする。** データ辞書とCSVを同時に添付すると、片方しか
  読まれないことがある。プロンプトは本文に貼り、CSVだけを添付するのが確実。
- `PastRuns` 列は1セル1〜3KBあり全体の大半を占める。読み込みが不安定なら
  この列を削ると激減する（近走の要約は他の列に入っている）。
- 出てきた答えは「アプリの合議と一致するか」で検算する。大きく食い違う場合は、
  LLMがC群（人気内包列）を独立した根拠として使っていないか疑う。

## 限界（承知の上で使うこと）

このプロンプトで的中率が上がる保証はありません。単勝は市場効率的で、
検証済みシグナルの効果も「人気薄帯で複勝率が数pp動く」程度です。
用途は**当てること**ではなく、**相手の絞り込みと危険な人気馬の回避**です。
