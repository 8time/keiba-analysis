# 競馬AI思考法（keiba-analysis の意思決定フレームワーク）

> **これは創作ではなく編纂である。** 本書のすべての判定基準は、このリポジトリで実施した
> leak-free バックテストの結論（`memory/verified_*.md` と `scripts/*_backtest.py`）から引いている。
> 一般的な競馬理論をLLMの知識から足してはならない（§7 禁止リスト）。
>
> モデル非依存。Fable / Opus / Sonnet のいずれでも、この順序・この基準で同じ結論に到達できる。
> 実装は `core/philosophy.py`（決定的ルールエンジン・LLM呼び出しなし）。

---

## 0. 大前提（これを外すと全部間違える）

**市場（オッズ）は極めて強い。** 単勝は全条件・全オッズ帯で控除率を超えるポケットが存在しない
（`verified_tansho_roi_efficient` / `scripts/roi_pattern_backtest.py`）。したがって我々の勝ち筋は
「市場より上手く勝ち馬を当てる」ことではない。勝ち筋は3つだけである：

1. **見送り** — 情報が足りない/妙味が無いレースを買わない
2. **券種選択** — 単勝でなく複勝・3連複など、市場の歪みが残る側で勝負する
3. **点数絞り** — 当たる組み合わせを増やすのではなく、外れる組み合わせを削る

「期待値100%超だから買う」は**採用しない**。EV（回収率）はモデル推定勝率×オッズであり、
そのモデル勝率自体が市場より正確である保証がない。EVは**表示のみ・学習隔離**とする。

**エッジの検定規約**：新しいシグナルは必ず「人気/オッズを統制した残差 z」と「1年holdoutでの安定性」で
評価する。単体の勝率・回収率が高いだけの指標は、ほぼ確実に人気に織込み済み（priced-in）である。

## 1. 思考の順序（ステップ0〜6）

| # | ステップ | 問い | 実装 |
|---|---|---|---|
| 0 | レース選別 | そもそもこのレースを買うか？荒れるか堅いか？ | `core/value_scanner.py` |
| 1 | 除外判定 | 来ない馬はどれか？ | `core/elim_cross.py` |
| 2 | 危険な人気馬 | 本命は信用できるか？ | `core/danger_gate.py` |
| 3 | 妙味馬の発掘 | 市場が見落としている人気薄はいるか？ | `core/value_scanner.py` / `core/lap33.py` |
| 4 | 軸の信頼度補強 | 本命を裏付ける独立材料はあるか？ | `core/corrected_time.py` / `core/blood_course.py` |
| 5 | 買い目構成 | どの券種で、何点に絞るか？ | `core/consensus_view.py` / `core/trio_engine.py` |

**順序に意味がある。** 0で「買わない」と決めたレースに1〜5を走らせても時間の無駄であり、
「せっかく分析したから買う」というコミットメント・バイアスを生む。0は必ず最初に置く。

## 2. 各ステップの判定基準

### ステップ0：レース選別

**(a) 見送り判定** — `race_skip_reasons()`
情報不足で読めないレースを機械的に外す：障害戦 / 新馬戦 / 未勝利戦 / 2歳戦 /
少頭数（10頭以下＝妙味なし）/ 単勝1倍台の大本命（リターン不足）。

**(b) 荒れ確率** — `arare_prob()`（凍結係数ロジット）
「3着内に7番人気以下が1頭以上入る」確率を返す。holdout AUC 0.69 / 上位20% precision 73%。
主係数は**オッズエントロピー（+0.90）**。手調整スコア（0.624）を上回る。

> **重要**：フィールドの実力拮抗度（補正Tや血統スコアの分散）は**荒れ判別に効かない**。
> 市場に織込み済みだった（`verified_arare_field_pricedin` / `scripts/scanner_arare_v2.py`）。
> 「実力が拮抗しているから荒れる」は直感的に正しく見えるが、その情報はすでにオッズに入っている。

オッズを超える独立した荒れ条件は3つだけ（`verified_arare_conditions`）：
- **ハンデ戦**（+7.9pp / z5.2）
- **フルゲート16頭**（z5.9）
- **オッズ本命不在**（`no_favorite_flag()`：1番人気≥3.0倍 かつ 3番人気/1番人気≤2.0 かつ 30倍未満が10頭以上）
  → 荒れ83% / z5.5。上2つと独立（`verified_arare_entropy`）
- 逆に**少頭数8-10頭は堅い**（本線 +8.4pp）

牝馬限定戦・ダートは荒れやすいが**人気に織込み済み**＝検索の絞り込みには使えるが買い妙味は無い。

**(c) レジーム判定** — `trio_lean()` → `②穴妙味向き` / `本線向き` / `中立`
以降のステップ3〜5の重み付けがこれで変わる。

### ステップ1：除外判定

`elim_cross.compute_flags()` が「来にくさフラグ」を返し、`verified_count()` がその**重複数**を数える。
検証済みの単調性：**重複が増えるほど複勝率が単調に低下**（絶対複勝率 31.5% → 10.3%）。

> **ただし単体のフラグは人気に織込み済み**（`project_elimination_engine`）。
> フラグ1個で切ってはいけない。**重複数**でのみ判断する。

- **人気薄（6番人気以下）**：重複 **3個以上**で切る
- **人気上位（1-5番人気）**：フラグが人気に二重計上されるため、重複 **5個以上**でのみ切る
  （`ELIM_CUT_POPULAR = 5`）
- **切らない例外（救済）**：以下のいずれかを持つ馬は消去フラグだけで切らない
  - combo≥2（荒れ予報6シグナルの複数一致・z+9.2）
  - 軸候補◎〇（オッズ実複勝率が上位＝最も直接的な3着内根拠）
  - 統合スコア上位1/3（最良予測器が生存と判定）
  - 妙味馬ハンター「🎯精鋭」（combo=0の好走馬の6割を捕捉・`project_value_horse_hunter`）
- **🛟ボーダー残し**：半分カット後に1頭戻す。3着内の取りこぼしが 15% → 10% に改善
  （複勝残差 +0.83pp / z2.0・**相手専用**）。代替不能と確定済み（`verified_keepone_border`）
- **🔥敗者復活**：切る帯（消去3+）でも combo≥3 なら複勝がベース超え
  （holdout 12.3% > 切る帯 5.9% / z+2.21）＝**最も過小評価された穴**

### ステップ2：危険な人気馬

`danger_gate.danger_veto()` が severity（0/1/2）と理由を返す。検証済みの危険材料：

| 材料 | 効果 | 出典 |
|---|---|---|
| **ガラス人気馬**（単複逆転：上位人気×単勝短×複勝薄） | z-8.5・3窓一貫 | `verified_odds_theory_signals` |
| **脆い本命**（1番人気に危険材料1つ） | 複勝 -6.5pp / z-10.1 | `verified_antimarket_elim` |
| **オッズ断層直下**（市場が見放した側） | -5.1pp / z-16.5 | 同上 |
| **人気馬×中9週以上の休養** | 複勝残差 z-5.6 | `verified_rotation_weight_demerit` |
| **半年休み明け** | 同系統 | 同上 |
| **外有利日×内枠の1-3番人気**（当日バイアス逆張り） | 弱いfade | `verified_emp_bias_danger` |
| **ダート内枠×4-5番人気** | -3.9pp / z-6.0 | `verified_dirt_draw_bias` |

> **決定的に重要な運用ルール**：危険人気馬は**軸から外さない**。
> 66レースの実運用台帳で「警告あり」の軸でも複勝的中 77.5%。**切ると損をする**。
> 危険材料は「本命の信頼度を下げる」情報であって「買うな」ではない。
> ROIがフラットな材料（中9週+など）は fade にも使えない＝**軸信頼度の減点にのみ使う**。

### ステップ3：妙味馬の発掘（人気薄限定）

以下は**すべて人気薄（6番人気以下）でのみ有効**。人気上位帯では priced-in になる。

| シグナル | 内容 | 検証 |
|---|---|---|
| 🔵補正T上位 | 同日同コース偏差で較正した自前タイム指数のtop3 | z+10.4（最強） |
| 🧬血統上位 | 父×BMS×距離適性スコアのtop3 | z+7.6 |
| 🧬血統回収100%+ | 父の同条件回収率が100%超 | z+6.4 |
| 👑騎手力top | jockey_power のtop3 | z+3.8 |
| ⚡33ラップ適合 | 中盤3F相当−上がり3F の適合判定 | z+2.6（`verified_lap33_theory`） |
| 🔥末脚top | 上がり3F偏差のtop3 | z+2.3（`verified_spurt_index`） |

**🧩combo（同時発火数）が単体より強い**（`verified_arare_signal_check`）：
combo≥2 で z+9.2、combo≥3 で z+8.2。**単体シグナル1個の馬を穴に採用してはいけない**
（⚡33などは全馬に出がち）。穴は **combo≥2** のゾーンに限る。

**末脚の質を見分ける**（`verified_spurt_pace_quality`）：
前走スロー由来の上がりtop3は次走 z+3.8〜8.5（🐢＝信頼）。
前走ハイペース由来（＝バテ差し）は z≈0（⚡＝priced-in・注意）。同じ「上がり最速」でも価値が違う。

**単複乖離**（`core/value_scanner.tanpuku_divergence`）：単勝≥10倍 かつ 複勝≤3倍
→ 勝率 2.5% → 7%（検証済み）。

### ステップ4：軸の信頼度補強（人気上位帯）

軸＝**3着内に来る信頼度（複勝率）が高い人気馬**。信頼度の基準は**単勝オッズ別の実複勝率**
（`axis_selector.ODDS_FUKU`・jravan.db 2021-25 実測）。1.0-1.2倍で94.9% / 2.6-3.0倍で64.3% /
4.5-6.0倍で45.2%。オッズは人気順位より遥かに細かい3着内指標である。

> 「2.5倍の崖」は存在しない。複勝率はオッズに対して滑らかに単調。資料の二分法は誤り
> （`scripts/axis_filters_backtest.py`）。

軸は **◎〇の2頭まで**。3番手▲は着内が「たまに」で迷いの元＝廃止済み。
検証でも固定軸（人気1位+2位）が最適だった（`project_axis_selection`）。

人気上位帯でのみ効く独立材料（**穴には効かない**ので注意）：
- **補正タイム**：本命補強に +5pp（穴には +1pp で織込み済み・`verified_corrected_time`）
- **道悪×血統POWER群**：米国型×稍重ダート×人気上位で複勝 +7.2pp / z+5.5（`verified_baba_blood`）
  ※ディープ/サンデー系の瞬発力は良馬場では効くが道悪では残差≈0に崩落
- **ダート外枠×1-3番人気**：+4.5pp / z+9.4（`verified_dirt_draw_bias`）
- **場×人気**：東京芝の1-3番人気 +3.7pp（全年プラス）/ 小倉芝 -3.0pp（`verified_blood_course`）
- **前走圧勝の人気馬**：軸から外すのは**誤り**。複勝率72.3%で最良の軸。罠は単勝券種限定
  （`verified_ohtani_trap`）
- **🏃本物の先行（平均通過位置が前方28%以内）も信頼度を割り引く**：生の複勝率は高い（44.1%）が、
  **オッズがそれ以上に高い**＝過剰人気。train -1.61pp/z-6.84・holdout -1.86pp/z-3.23
  （`scripts/pci_front_axis_backtest.py`）。前走1着とは**独立**に効く（重複を除いた純粋分でも
  train z-4.00 / holdout z-2.44）。両方を持つ馬が最悪（-4.6pp / -3.4pp）。
  **最も信頼できる軸は「先行でも前走1着でもない人気馬」**（+0.82pp / +1.00pp・両窓★）。
  → `FRONT_DEMERIT = 1.2pp`。`verified_legtype_axis`（脚質は織込み済み）と矛盾しない。
  あちらは生の複勝率、こちらはオッズ統制後の残差を見ている。
- **🔨前走1着（勝ち上がり直後）は信頼度を割り引く**：複勝率の絶対値は高い（44.5%）が、
  **同じオッズ帯の平均より約2pp低い**＝オッズほどには信頼できない
  （train -1.28pp/z-7.18・holdout -2.28pp/z-2.62・`scripts/axis_ng_backtest.py`）。
  重要なのは**圧勝かどうかを問わない**こと。勝ち幅0.3〜1.0秒の普通の勝ち馬も負（holdout z-2.66）。
  → 軸から**外さない**が、複勝信頼度から `PREV_WIN_DEMERIT = 1.5pp` を引く。
  俗に言う「昇級初戦・連勝馬の過剰人気」の正体はこれ（クラス列がDBに無いため前走1着で近似）。

### ステップ5：買い目構成

`consensus_view.integrate()` が、独立した検証済みエッジを**レジーム別に合議**して
本命/相手/押さえ/穴/切る に再編する。

**合議（votes）の検証結果**：一致数が増えると複勝率が単調に上がる。
ベース 9.4% → votes=2 で 16% → votes=3 で **27%**（`scripts/consensus_backtest.py`）。

> **正直な限界**：votes=3 でも ROI は最大 96%。**フラット単勝では黒字化しない。**
> 合議は「市場を出し抜く予測器」ではなく「**本命の信頼度を測り、相手/穴を絞る道具**」である。

**券種**：3連単フォーメーションは実配当（DBの payouts）で実ROI検証済み
（`verified_formation_roi`）。可変（レジーム連動）＋荒れ選択で控除率floor（75%）を有意に超える
（bootstrap CI下限 > 75%）が、**ROI中央値は 83-90% で 100% に届いていない**。
荒れ確率 ≥62% のレースが最良（中央90%）。**単年の少標本で100%超が出ても、それは変動の幻。**

**3連複の決着型**：①人気-人気-穴 が最頻（46%）でROIも最高（`project_trio_engine`）。

### ステップ6：反対役チェック

反対役は人格ではなく**手続き**である。以下を毎回問う：

1. **このシグナルは priced-in ではないか？** — 単体の勝率が高いだけの指標は、ほぼ市場に入っている。
   人気/オッズを統制した残差で見たか？
2. **これはリークではないか？** — 結果脚質（`kyakushitsu`）・通過順・確定オッズ後の情報は
   すべてリーク源。過去に「複勝combo+EVのROI123%」「ショッカー理論の馬連600%」「逆ショッカー128%」
   がすべてリークの幻だった（`verified_fukusho_combo_leak` / `verified_shocker_leak`）。
3. **本命の信頼度は足りているか？** — ステップ2の危険材料と、ステップ4の複勝信頼度（オッズ実測）を
   突き合わせる。信頼度がフロアを割り、かつ危険材料がある → **ステップ0の見送りに差し戻す**。
4. **小標本のノイズではないか？** — 1年holdoutで崩れる特徴は不採用。
   `verified_prior_margin_debunk`（前走着差0.8秒で155%）は全部これだった。

## 3. 除外ルール（検証済み / 観測台帳の区別）

**検証済み（backtest 裏付けあり）**：
- 消去クロスの**重複数**による切り（単調な複勝率低下・上記ステップ1の閾値）
- 危険人気馬の severity（ただし**軸からは外さない**＝減点のみ）
- 🛟ボーダー残し・🔥敗者復活

**観測台帳ベース（個人の実観測・検証外）**：
- `core/elim_reasons.py`（🎯消去理由ラーニング）：同じ条件タグが3回出たら自動で残す。
  これは**ユーザー個人の観測記録**であって統計的検証を経ていない。混同しないこと。
- `core/paddock_ledger.py`（👁️パドック観察タグ）：同上。馬体重/増減の定量部分だけは
  fade側（小型/大幅増減＝危険）で検証済み。歩様・発汗などの主観項目は履歴が無く検証不能
  （`verified_paddock_weight`）。

**データが存在せず実装不可能**：落馬歴・獣医診断・調子不良・クッション値・含水率・
複勝オッズ時系列・馬主エッジ。

## 4. 「買える／見送り」判定ロジック

```
IF 見送り理由（障害/新馬/未勝利/2歳/少頭数/1倍台本命）がある
    → 見送り
IF 本命の複勝信頼度 < フロア AND 本命に危険材料あり
    → 見送り（軸が立たないレースは点数が増えるだけ）
IF 荒れ確率が高い（≥62%）AND 穴（combo≥2）が存在する
    → 3連複/3連単フォーメーション・穴を3列目に厚く
IF 本線向き AND 軸候補◎〇が立つ
    → 本命から手堅く。点数は絞る
ELSE
    → 中立。相手を広げすぎない
```

**「EV > 100 なら買い」は使わない。** 上記のとおり単勝は市場効率的で、EVはモデル推定勝率に
依存する目安に過ぎない。買う/買わないは**情報の質（見送り条件）と軸の信頼度**で決める。

## 5. 反対役の視点（常設）

- 予想が「きれいに」まとまったときほど疑う。**きれいな物語は、たいてい priced-in か leak**。
- 「この馬を推す根拠は、市場が知らない情報か？」— 知っている情報なら妙味はない。
- 「見落としている来ない理由（消去フラグの重複）はないか？」
- 「より上位の馬がいないか？」— 統合スコア上位1/3を無視して穴に飛びついていないか。
- **打ち切る勇気**：PCI・風・マクリ・巻き返し・俗説5案は、すべて期待して検証して、
  ゼロだったので**打ち切った**。効かないものを「もう少し工夫すれば」と粘るのが最大の時間浪費。

## 6. 特徴量の優先順位

**荒れレース × 人気薄** で見るべき列（z値の降順・`verified_arare_signal_check`）：

1. **🔵補正T**（z+10.4）— 最強
2. **🧬血統スコア**（z+7.6）/ **🧬血統回収率100%+**（z+6.4）
3. **👑騎手力**（z+3.8）
4. **⚡33ラップ**（z+2.6）
5. **🔥末脚指数**（z+2.3）
6. ❌ 初ブリンカー — **不採用**（有意でない）

**そして最重要：🧩combo（2個以上の同時発火）は、どの単体シグナルよりも強い。**
単体の列を見るのではなく、**重複を見る**。

**本命（人気上位）で見るべき列**：単勝オッズ（実複勝率）＞ 補正T ＞ 道悪×血統 ＞ 枠 ＞ 場相性。

## 7. 禁止リスト（反証済み・再発明防止）

## 8. 使い方と、後から増やす／直す手順

### 実装との対応
- **エンジン**：`core/philosophy.py` が本書のステップ0〜6（＋⑧自分のルール）を関数化している。
  SRA（🏠 Single Race Analysis）の「🧠 開発者の思考」で毎レース実行される。LLM呼び出しは無い。
- **設定**：`philosophy.json`。3層に分かれている：

| 層 | 変えられるもの | どこで |
|---|---|---|
| ON/OFF | ステップごとに思考を使う／使わない | 画面のチェックボックス |
| 強度 | 厳しめ / 標準 / ゆるめ | 画面のプルダウン |
| 調整値 | 閾値そのもの（信頼度フロア%、穴のcombo数、相手の頭数 …） | 画面「🔧 細かい数値を調整する」／`params` |

### 調整値（`PARAM_SPECS`）
`core/philosophy.py` の `PARAM_SPECS` に定義。`philosophy.json` の
`steps[key]["params"][name]` に書くと強度の既定値より優先される。

| ステップ | 調整値 | 既定（厳しめ / 標準 / ゆるめ） |
|---|---|---|
| ① レース選別 | 見送りにする「情報不足の理由」の数 | 1 / 2 / 0（=見送り判定OFF） |
| ① レース選別 | 「荒れ寄り」とみなす荒れ確率 | 62%（共通） |
| ② 消す | 「要注意」に挙げる来にくさフラグ数 | 2（共通・厳しめ時のみ表示） |
| ④ 妙味馬 | 穴に採用する好材料の重複数 | 3 / 2 / 2（+🎯精鋭） |
| ⑤ 軸の裏取り | 本命に求める複勝信頼度 | 55% / 45% / 35% |
| ⑥ 買い目 | 相手（2列目）の頭数 | 2 / 3 / 5 |

> **調整値で変えられるのは「絞り込みの厳しさ」だけ**であり、検証で出た数値（複勝率テーブル・z値・
> 荒れロジット係数）は動かせない。設定をいじっても検証結果の書き換えにはならない。

### ⑧ 自分のルール（検証外）
思いついた判断を後から足すための場所。参照できるのは**既に計算済みの値だけ**
（人気 / 単勝オッズ / 好材料の重複数 / 来にくさフラグ数）で、新しい指標は作れない。
`{項目} が {値} {以上|以下} なら {注意|消し}` の形。本命と穴は誤爆防止のため消されない。

> **①〜⑦（検証済み）と⑧（個人ルール）は必ず分けて表示する。**
> `core/elim_reasons.py`（消去理由ラーニング）や `core/paddock_ledger.py`（パドック台帳）と
> 同じ「観測台帳」の扱い。統計的裏付けが無いことを画面にも明記している。

### 新しいステップを足す（コード編集が必要）
1. `core/philosophy.py` の `STEPS` に1行足す（key・番号・名前・平易な説明）
2. `_step_xxx(cfg, ...)` を書く。**入力は既に計算済みの結果だけ**を受け取り、
   `{'verdict': ..., 'reasons': [日本語の理由文]}` を返す純関数にする
3. `think()` の `_run('xxx', ...)` に1行足す
4. 閾値があれば `PARAM_SPECS` に選択肢付きで定義する（**連続スライダーは使わない**）

### 新しい判断軸を足したくなったら
本書に足す前に、**必ずバックテストする**。順序を逆にしない。
- §7 の禁止リストにある項目は再検証しない（すでに答えが出ている）
- 新規検証の作法は `repo/fable_brief_*.md` のフォーマットに従う
- 検証を通る前の思いつきは、⑧の個人ルールに置いて運用しながら様子を見る
  （`feedback_single_day_hunch_check`：思いつきはまず1日分で試算してから本格検証を判断する）
